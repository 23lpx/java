# 部署基础

## 621. Docker 是什么？

**面试回答**

Docker 是一个容器化平台，能把应用及其依赖打包成一个标准化的「容器」，在任意装了 Docker 的机器上一致地运行，实现「一次构建、到处运行」。

**理解**

Docker 把「应用 + 运行环境（依赖、配置、库）」一起打包进容器，容器之间隔离、互不影响。它比虚拟机轻量（共享宿主内核，不虚拟整个操作系统）。开发者打包好镜像，任何环境拉下来跑都一样，解决「我本地能跑、服务器跑不了」的环境不一致问题。

**场景**

项目里把 Spring Boot 应用打成 Docker 镜像，部署时用容器跑，保证开发、测试、生产环境一致。

**常见追问**

- Docker 解决什么？（环境一致、轻量隔离）
- 和虚拟机区别？（更轻量，共享内核）

**易错点**

Docker 是「容器化」，比虚拟机轻量；核心价值是「环境一致 + 轻量隔离」。

## 622. Docker 解决什么问题？

**面试回答**

解决环境不一致和部署繁琐问题：把应用和依赖打包成镜像，保证开发/测试/生产环境一致，避免「本地能跑、上线报错」；同时隔离、轻量、方便部署和扩展。

**理解**

传统部署：每台机器要装 JDK、配置、依赖，环境不一致常导致线上出问题。Docker 把环境打进镜像，处处一致。它还带来隔离（一个容器一个应用，互不干扰）、轻量（比虚拟机省资源）、可快速启动和扩展（起多个容器做负载）。是云原生和微服务部署的基础。

**场景**

项目用 Docker 部署，镜像里包含 JDK 和应用，任何服务器 pull 下来跑都一样，快速起多个实例扩容。

**常见追问**

- 主要解决什么？（环境一致、部署方便）
- 还有什么好处？（隔离、轻量、易扩展）

**易错点**

Docker 最核心是「环境一致」，其次才是隔离、轻量；别只答「能打包」。

## 623. 镜像和容器有什么区别？

**面试回答**

镜像是只读的「模板」，包含应用和运行环境；容器是镜像「运行起来」的实例，是可读写的运行状态。一个镜像可以启动多个容器，关系类似「类」和「对象」。

**理解**

镜像（Image）是静态的构建产物，定义了容器里有什么（文件系统、依赖、启动命令），只读不可改。容器（Container）是镜像的运行时实例，在镜像之上加了一层可写层，跑起来后有进程、状态。用「类与对象」理解：镜像是类，容器是 new 出来的对象，一个镜像能起多个容器。

**场景**

项目里先 docker build 出镜像，再 docker run 用镜像启动容器；同一镜像可起多个容器做扩容。

**常见追问**

- 镜像是什么？（只读模板）
- 容器是什么？（镜像运行起来的实例）
- 一个镜像能起几个容器？（多个）

**易错点**

镜像是「静态模板」、容器是「运行实例」；类比「类与对象」最贴切，一个镜像可起多个容器。

## 624. Nginx 是什么？

**面试回答**

Nginx 是一个高性能的 Web 服务器和反向代理服务器，能处理大量并发连接，常用于静态资源托管、反向代理、负载均衡等。

**理解**

Nginx 是轻量、高性能的服务器，以「高并发、低内存」著称（基于事件驱动，一个进程能处理大量连接）。它既能直接当 Web 服务器托管静态文件，又能作为「反向代理」把请求转发给后端的应用服务器（如 Tomcat），还能做负载均衡、HTTPS 等。是后端部署里常见的「入口」。

**场景**

项目里用 Nginx 托管前端静态页面、把 API 请求反向代理到后端 Spring Boot 服务、并做负载均衡。

**常见追问**

- Nginx 是什么？（高性能 Web/反向代理服务器）
- 它擅长什么？（高并发、静态资源、反向代理、负载均衡）

**易错点**

Nginx 是「Web 服务器 + 反向代理」，常作为流量入口；不是应用服务器（不跑业务逻辑）。

## 625. Nginx 常见用途有哪些？

**面试回答**

常见用途：①静态资源托管（直接返回 HTML/JS/CSS/图片）；②反向代理（转发请求到后端应用）；③负载均衡（把请求分发给多个后端实例）；④HTTPS 配置；⑤限流、缓存、跨域等。

**理解**

Nginx 作为入口，承担多种职责：托管前端静态文件（快）；反向代理把 /api 请求转给后端 Tomcat；负载均衡用轮询等策略把流量分到多个后端实例；配置 SSL 证书提供 HTTPS；还能做限流、gzip 压缩、缓存等。核心是「流量入口的调度和管理」。

**场景**

项目里 Nginx 既托管前端页面，又把接口请求反向代理到多个后端实例并负载均衡，同时配置 HTTPS。

**常见追问**

- 最核心的两个用途？（反向代理、负载均衡）
- 还能做什么？（静态资源、HTTPS、限流）

**易错点**

Nginx 的用途核心是「反向代理 + 负载均衡 + 静态资源」，作为流量入口统一调度。

## 626. 什么是反向代理？

**面试回答**

反向代理指代理服务器（如 Nginx）接收客户端的请求，再把请求转发给后端真实的服务器处理，把结果返回给客户端；客户端只和代理交互，不知道后端是谁，后端服务器也不直接暴露给外部。

**理解**

「反向」是相对「正向代理」（代理客户端访问外部）而言：反向代理是「代理服务器」，站在服务端一侧。客户端请求先到 Nginx，Nginx 决定转发给哪台后端，后端处理完经 Nginx 返回。好处：隐藏后端真实地址、统一入口、负载均衡、安全防护、统一加 HTTPS 等。

**场景**

项目里客户端请求打到 Nginx，Nginx 反向代理转发给内网的 Spring Boot 服务，外部只看到 Nginx、不知道后端地址。

**常见追问**

- 反向代理站在哪边？（服务端，代理后端）
- 好处？（隐藏后端、统一入口、负载均衡）

**易错点**

反向代理是「代理服务端」、正向代理是「代理客户端」；别搞反方向。它常与负载均衡一起出现。

## 627. 什么是负载均衡？

**面试回答**

负载均衡是把大量请求按一定策略（如轮询、最少连接、按权重）分发到多台后端服务器上，避免单台压力过大，提高系统的可用性和处理能力。

**理解**

单台服务器能力有限，用户多了扛不住。负载均衡器（如 Nginx）作为入口，把请求分摊给多个后端实例，让整体吞吐量提升、单点不成为瓶颈。策略有：轮询（依次分）、加权轮询（按服务器性能分权重）、最少连接（分给连接最少的）、IP 哈希（同一 IP 固定到同一台）等。

**场景**

项目里 Nginx 用轮询策略把请求分发到多个 Spring Boot 实例，提升并发处理能力、避免单点故障。

**常见追问**

- 负载均衡解决什么？（分摊压力、提高可用性）
- 常见策略？（轮询、加权、最少连接、IP 哈希）

**易错点**

负载均衡是「把请求分摊到多台后端」；常见策略（轮询、加权、最少连接）要能说出一两个。
