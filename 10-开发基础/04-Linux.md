# Linux

## 572. `ls` 有什么作用？

**面试回答**

ls 用于列出目录下的文件和子目录，是最常用的查看目录内容的命令；加参数如 `ls -l` 显示详细信息、`ls -a` 显示隐藏文件。

**理解**

ls（list）默认列出当前目录的文件名。常用参数：`-l` 长格式（权限、大小、时间等）、`-a` 显示隐藏文件（以 . 开头）、`-h` 人类可读的大小、`-t` 按时间排序。组合用如 `ls -lh`。

**场景**

项目部署后进目录 `ls -l` 看有哪些文件、权限、大小，确认 jar 包、日志文件都在。

**常见追问**

- ls 干嘛？（列目录内容）
- 看详细信息加什么？（-l）

**易错点**

ls 是「列出目录内容」；`-l` 看详情、`-a` 看隐藏文件，这些常用参数要熟。

## 573. `cd` 有什么作用？

**面试回答**

cd 用于切换当前工作目录（change directory），进入指定目录；如 `cd /path`、`cd ..` 回上级、`cd ~` 回家目录。

**理解**

cd 是最基本的目录导航命令。常用：`cd 目录名` 进入、`cd ..` 返回上一级、`cd ~` 或 `cd` 回用户主目录、`cd /` 到根目录。Linux 用绝对路径或相对路径定位。

**场景**

项目里 `cd /usr/local/app` 进入应用目录，`cd ..` 回到上级。

**常见追问**

- cd 干嘛？（切换目录）
- 回上级？（cd ..）回家目录？（cd ~）

**易错点**

cd 是「切换目录」；`..` 表上级、`~` 表家目录，这些符号要记住。

## 574. `pwd` 有什么作用？

**面试回答**

pwd 用于显示当前所在的完整目录路径（print working directory），告诉你现在在哪个目录下。

**理解**

pwd 打印当前工作目录的绝对路径。在目录里迷路时，pwd 一下就知道自己在哪，配合 cd 使用。它没有参数，直接输 pwd 即可。

**场景**

项目里切了好几个目录后，`pwd` 确认当前在哪个目录，避免在错误目录下操作。

**常见追问**

- pwd 干嘛？（显示当前目录路径）
- 输出什么？（绝对路径）

**易错点**

pwd 是「显示当前目录绝对路径」，用于确认位置，简单但常用。

## 575. 如何查看文件内容？

**面试回答**

常用命令：`cat` 一次性显示全部内容（适合小文件）、`more`/`less` 分页查看（可上下翻页）、`head` 看开头几行、`tail` 看末尾几行。大文件用 less 或 tail 更合适。

**理解**

查看文件有多个命令，按场景选：cat 直接全打印，文件大就刷屏；less 能分页、翻页、搜索（按 q 退出）；head -n 看前几行；tail -n 看后几行（tail -f 还能实时跟踪，常看日志）。查日志最常用 tail。

**场景**

项目里查配置用 `cat application.yml`；查日志用 `tail -f xxx.log` 实时看最新日志。

**常见追问**

- 一次性看全部？（cat）分页看？（less）
- 看末尾/实时看？（tail / tail -f）

**易错点**

查日志最常用 `tail -f` 实时跟踪；大文件别用 cat 会刷屏，用 less 或 tail。

## 576. 如何实时查看日志？

**面试回答**

用 `tail -f 日志文件` 实时跟踪文件末尾新增的内容，日志一有新输出就立刻显示出来，常用于观察运行中的程序日志。

**理解**

tail -f 会「持续监听」文件：文件末尾追加新内容时，立刻打印出来，不会退出（按 Ctrl+C 退出）。`tail -f` 是排查线上问题、观察服务启动、看请求日志的标配命令。类似的 `tail -n 100 -f` 先看最后 100 行再跟踪。

**场景**

项目里启动服务后 `tail -f app.log` 盯着日志看启动过程、实时看请求和异常。

**常见追问**

- 实时看日志用？（tail -f）
- 怎么退出？（Ctrl+C）

**易错点**

实时看日志的核心命令是 `tail -f`；它持续输出不退出，用 Ctrl+C 停止。

## 577. 如何搜索日志中的关键字？

**面试回答**

用 grep 过滤：`grep "关键字" 日志文件` 找出含关键字的行，常配合 `tail -f 日志 | grep 关键字` 实时过滤，或用 `grep -C` 看上下文。

**理解**

grep 是文本过滤利器：在文件里搜包含某关键字的行。常用：`grep "ERROR" app.log` 找错误行；`grep -i` 忽略大小写；`grep -n` 显示行号；`grep -C 3` 显示匹配行前后各 3 行（上下文）。实时场景 `tail -f app.log | grep "订单"` 只显示含「订单」的新日志。

**场景**

项目里日志量大，用 `grep "订单号" app.log` 定位某个请求，或用 `tail -f app.log | grep ERROR` 只看报错。

**常见追问**

- 搜关键字用？（grep）
- 看匹配行上下文？（grep -C n）

**易错点**

搜索日志关键字用 grep；`tail -f ... | grep` 是「实时过滤」，是排查的常用组合。

## 578. 如何查看当前运行的 Java 进程？

**面试回答**

用 `jps` 查看 Java 进程（JDK 自带，列出进程号 PID 和主类/包名）；或 `ps -ef | grep java` 查看所有 Java 相关进程。两者都能拿到 Java 进程的 PID。

**理解**

jps 是 JDK 自带命令，专门列 Java 进程，输出简单（PID + 类名/jar 名）。ps -ef | grep java 更通用，能看进程的启动参数、用户等详细信息。拿到 PID 后可用于 jstack 查线程、kill 停进程等。

**场景**

项目部署后 `jps` 找 Java 进程 PID，再配合 jstack 排查线程或 kill 重启服务。

**常见追问**

- 看 Java 进程用？（jps，或 ps -ef | grep java）
- jps 输出什么？（PID 和类/jar 名）

**易错点**

jps 是「JDK 自带、专查 Java 进程」；ps -ef | grep java 更通用、信息更全，两者都会用。

## 579. 如何查看端口占用？

**面试回答**

用 `netstat -tunlp | grep 端口号` 或 `lsof -i:端口号` 查看哪个进程占用了该端口，能拿到进程 PID。

**理解**

端口被占用是部署常见问题（如 8080 被占导致服务起不来）。netstat -tunlp 列出所有监听的端口和对应进程，再 grep 过滤出目标端口；lsof -i:8080 直接看 8080 被谁占用。拿到 PID 后可 kill 释放端口。

**场景**

项目启动报端口占用，用 `netstat -tunlp | grep 8080` 找到占用进程，kill 后重启。

**常见追问**

- 查端口占用用？（netstat -tunlp | grep 端口，或 lsof -i:端口）
- 查到的 PID 用来干嘛？（kill 结束进程）

**易错点**

netstat 配合 grep 查端口占用是高频命令；查到 PID 后要确认是谁再决定是否 kill。

## 580. 如何结束一个进程？

**面试回答**

用 kill 命令结束进程：`kill PID` 优雅终止（发 TERM 信号），`kill -9 PID` 强制杀死（发 KILL 信号，不给清理机会）。一般先 kill，无效再 kill -9。

**理解**

kill 本质是「给进程发信号」。默认 kill 发 SIGTERM，让进程有机会做清理后退出；kill -9 发 SIGKILL，强制立刻终止，进程来不及释放资源。所以优先用 kill（优雅），程序不响应再 kill -9。要拿到 PID（用 jps、ps、netstat 查）。

**场景**

项目里要重启服务，先 `kill PID` 优雅停，若卡住再 `kill -9 PID` 强杀，然后重新启动。

**常见追问**

- 结束进程用？（kill PID）
- 强杀用？（kill -9 PID）
- 两者区别？（优雅 vs 强制）

**易错点**

kill 优先、kill -9 兜底；-9 是强制杀、不清理，别一上来就用。

## 581. `chmod` 是什么？

**面试回答**

chmod 用于修改文件或目录的权限（change mode），控制谁能读、写、执行该文件，如 `chmod 755 文件` 或 `chmod +x 脚本`。

**理解**

chmod 设置文件的读(r)、写(w)、执行(x)权限，分三类对象：所有者(u)、所属组(g)、其他人(o)。可以用数字表示：r=4、w=2、x=1，三位数字分别对应用户/组/其他人（如 755 = 所有者 rwx、组 r-x、其他人 r-x）。也可用符号 `chmod +x` 加执行权限。

**场景**

项目里给启动脚本 `chmod +x start.sh` 加执行权限，才能直接运行；给文件设合适权限防止别人乱改。

**常见追问**

- chmod 干嘛？（改文件权限）
- 755 什么意思？（所有者 rwx，组和其他人 r-x）
- 加执行权限？（chmod +x）

**易错点**

权限用数字 r=4/w=2/x=1 计算；755 是常见值，要理解「所有者/组/其他人」三组权限。

## 582. Linux 文件权限分别表示什么？

**面试回答**

Linux 文件权限分读(r)、写(w)、执行(x)三种，分别对应三类用户：所有者(user)、所属组(group)、其他人(other)。用 `ls -l` 看到的 `-rwxr-xr-x` 就表示这三组权限。

**理解**

`ls -l` 权限列如 `-rwxr-xr-x`：第一位是文件类型（- 普通文件、d 目录），后面 9 位分三组——前 3 位所有者、中 3 位所属组、后 3 位其他人，每组按 rwx 顺序。r 读、w 写、x 执行（目录的 x 表示能否进入）。数字 r=4、w=2、x=1，相加得 755 这种表示。

**场景**

项目里 `ls -l` 看文件权限，确认脚本有 x 执行权限、配置文件的写权限只给了所有者。

**常见追问**

- r、w、x 分别？（读、写、执行）
- 三组用户？（所有者、所属组、其他人）
- 755 怎么算？（r4+w2+x1 组合）

**易错点**

权限是「三种权限 × 三类用户」；ls -l 的 9 位分三组，每组 rwx，别和「文件类型」那一位搞混。
