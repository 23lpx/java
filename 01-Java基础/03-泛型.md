# 泛型

## 35. Java 泛型是什么？

**面试回答**

泛型是一种「参数化类型」的机制，让类、接口、方法在定义时不指定具体类型，使用时再传入类型，例如 `List<String>`。

**理解**

在泛型出现前，集合里什么都放（都是 Object），取出来要强转，类型不安全。泛型用类型参数 `T`、`E` 等占位，编译期就能做类型检查，运行时通过擦除保证兼容。它本质是把「运行时才暴露的类型错误」提前到「编译期」。

**场景**

项目里 `List<Dish>`、`Map<String, Object>`、统一响应体 `Result<T>` 都是泛型，明确集合里装什么、接口返回什么。

**常见追问**

- 泛型用在哪？（类、接口、方法）
- 泛型是运行时生效吗？（不是，编译期检查，运行时擦除）

**易错点**

泛型只支持引用类型，`List<int>` 是不合法的，要用 `List<Integer>`。

## 36. 为什么需要泛型？

**面试回答**

没有泛型时，集合里存的都是 Object，取出来必须手动强转，一旦转错类型，编译期发现不了，运行时会抛 `ClassCastException`。泛型就是为解决这个类型安全问题。

**理解**

泛型出现前写 `List list = new ArrayList(); list.add("a"); Integer i = (Integer) list.get(0);` 编译能过但运行报错。有了泛型，`List<String>` 只能放 String，取出来不用强转，类型错误在编译期就暴露。它同时解决了「类型安全」和「少写强转」两个问题。

**场景**

项目里所有集合都用泛型声明元素类型，从 Map 取值时编译器会保证类型一致，避免运行期 ClassCastException。

**常见追问**

- 泛型和强制类型转换比优势在哪？（编译期检查 + 不用手动强转）

**易错点**

泛型是编译期保障，运行时类型信息会被擦除，所以它不能完全替代所有类型判断。

## 37. 泛型有什么好处？

**面试回答**

三个好处：编译期类型检查，提前发现错误；消除强转，代码更简洁；代码复用，一个类/方法适配多种类型。

**理解**

类型安全是最核心的好处，把运行期错误提前到编译期；同时省去 `(String)` 这类强转，代码可读性高；泛型类 `Result<T>` 写一次就能适配所有返回类型，避免为每种类型重复写代码。

**场景**

项目的统一响应体 `Result<T>` 一个类就覆盖了 `Result<Dish>`、`Result<Order>` 等所有场景，这就是泛型复用的体现。

**常见追问**

- 泛型有缺点吗？（类型擦除导致运行时拿不到类型信息、不能 new 泛型数组等）

**易错点**

好处要落到「编译期检查 + 消除强转 + 复用」三点，别只背「类型安全」一句。

## 38. 泛型类、泛型方法分别是什么？

**面试回答**

泛型类是在类名后带类型参数，如 `class Result<T>`；泛型方法是在方法返回值前带类型参数，如 `<T> T getData()`。

**理解**

泛型类的类型参数作用于整个类，创建实例时指定；泛型方法的类型参数只作用于该方法，每次调用独立推断，静态方法也可以用泛型方法（因为不依赖实例）。两者可以独立使用。

**场景**

项目里 `Result<T>` 是泛型类；工具方法如 `<T> T getBean(Class<T> clazz)` 是泛型方法，常见于获取 Spring Bean 的场景。

**常见追问**

- 泛型方法怎么定义？（返回值前加 `<T>`）
- 静态方法能用泛型类的 T 吗？（不能，静态方法要用泛型方法自己声明 `<T>`）

**易错点**

泛型方法要在返回值前加 `<T>` 声明，直接写 `public T getData()` 而类上没声明 T，是编译不过的。

## 39. `<?>` 是什么意思？

**面试回答**

`<?>` 是通配符，表示「某种未知类型」，用在泛型的类型参数位置，代表任意类型。

**理解**

`List<?>` 表示「某种类型的 List」，但具体类型未知，所以只能读、不能往里写（除了 null），因为编译器不知道放进去什么类型是安全的。它常用于只想遍历读取、不关心具体类型的场景。

**场景**

写一个方法只遍历打印任意类型的 List 时，参数写成 `List<?>`，比 `List<Object>` 更通用（`List<String>` 不是 `List<Object>` 的子类型）。

**常见追问**

- `List<?>` 和 `List<Object>` 一样吗？（不一样，`List<String>` 能传给 `List<?>`，不能传给 `List<Object>`）
- 通配符能写元素吗？（不能，只能读）

**易错点**

`List<?>` 只能读不能写（null 除外），因为具体类型未知，往里 add 任何对象都不安全。

## 40. `<? extends T>` 和 `<? super T>` 有什么区别？

**面试回答**

`<? extends T>` 是上界通配符，表示 T 或 T 的子类，只能读不能写；`<? super T>` 是下界通配符，表示 T 或 T 的父类，只能写不能读（读出来是 Object）。

**理解**

记住 PECS 原则：Producer（生产者，往外给数据）用 `extends`，Consumer（消费者，往里存数据）用 `super`。`extends` 时类型最高是 T，取出来的东西能安全当作 T 处理，但写入不安全（不知道具体子类）；`super` 时类型最低是 T，写入 T 一定安全，但取出来只能当 Object。

**场景**

把一组菜品按某个比较器排序时，如果方法参数要接收「能比较的列表」，用 `List<? extends Comparable>`；把数据写进某个集合时用 `? super`。

**常见追问**

- PECS 是什么？（Producer Extends、Consumer Super）
- 为什么 extends 不能写？（具体子类类型未知，写入不安全）

**易错点**

记反方向是高频错误：`extends` 是「上界、T 及其子类」，`super` 是「下界、T 及其父类」，别背混。

## 41. 什么是泛型擦除？

**面试回答**

泛型擦除指编译后泛型类型信息会被去掉，类型参数被替换成它的边界（默认是 Object），运行时 JVM 并不知道泛型的具体类型。

**理解**

Java 泛型是「编译期特性」：编译器做类型检查后，会把 `List<String>` 和 `List<Integer>` 都擦成 `List`，运行时代码里拿不到 `<String>` 这个信息。这样做的目的是为了向后兼容——Java 5 引入泛型时，能和之前没有泛型的代码共存。代价是运行时不能 `new T()`、不能判断 `instanceof List<String>`、不能创建泛型数组。

**场景**

面试常考：`List<String>` 和 `List<Integer>` 在运行时是同一个 Class（都是 List），不能靠 `instanceof` 区分泛型类型；项目里反射获取泛型时拿到的也是擦除后的类型。

**常见追问**

- 擦除后 T 被替换成什么？（默认 Object，有边界时替换成边界类型）
- 擦除带来什么限制？（不能 new T、不能 instanceof 泛型、不能创建泛型数组）

**易错点**

泛型信息在「运行时」是拿不到的，别误以为 `list instanceof List<String>` 能通过编译（这本身就编译错误）。
