# 集合

## 42. Java 常用集合有哪些？

**面试回答**

Java Collections Framework 主要包含 `Collection` 与 `Map` 两条体系。Collection 下常用 `List`、`Set`、`Queue`、`Deque`；Map 保存键值映射。常见实现有 ArrayList、LinkedList、HashSet、LinkedHashSet、TreeSet、HashMap、LinkedHashMap、TreeMap、ArrayDeque 和 ConcurrentHashMap。

**原理与理解**

接口表达语义，实现类决定顺序、空值、复杂度与并发特性。Java 21 又引入 `SequencedCollection`、`SequencedSet`、`SequencedMap`，统一表达有明确首尾和反向视图的集合。

**成立条件与边界**

Map 不继承 Collection；Set 也不能一概说成“无序”，LinkedHashSet、TreeSet 都有明确迭代顺序。并非所有实现都允许 null 或所有修改操作，必须查看具体契约。

**实际场景（通用工程）**

分页结果通常用 List；需要成员唯一性用 Set；按 ID 找对象用 Map；FIFO/LIFO 用 Deque；跨线程共享映射再评估 ConcurrentHashMap，而不是只凭名称选择。

**常见追问**

- Collection 与 Map 有继承关系吗？（没有）
- Queue 与 Deque 有何关系？（Deque 支持两端操作，并继承 Queue）

**易错点**

不要只背“List、Set、Map 三类”；Queue/Deque、并发集合和 Java 21 的顺序集合接口也是知识地图的一部分。

## 43. List、Set、Map 有什么区别？

**面试回答**

List 是有索引和明确迭代顺序的元素序列，通常允许重复；Set 不允许按 equals 语义重复的元素；Map 保存 key 到 value 的映射，key 在 Map 的相等语义下唯一。具体顺序与 null 支持由实现决定。

**原理与理解**

List 按位置组织元素。Set 的核心是成员唯一性，不是“没有顺序”；HashSet 不保证迭代顺序，LinkedHashSet 保持 encounter order，TreeSet 按排序规则组织。Map 的 value 可重复，但同一 key 再 put 通常替换映射。

**成立条件与边界**

可变对象作为 Set 元素或 Map key 后，若修改了参与 equals/hashCode 或排序的字段，容器可能无法正确查找。不可修改集合也可能拒绝 add/remove；null 并非接口统一保证。

**实际场景（通用工程）**

订单明细保留顺序用 List；去重后的业务 ID 用 Set；按订单号定位订单用 Map。HashSet 去重机制见 [[04-集合#53. HashSet 为什么可以去重？]]。

**常见追问**

- Set 都无序吗？（不是，取决于实现）
- Map 的 key 相同会怎样？（通常替换旧 value，并返回旧值）

**易错点**

“有序”应说明是索引顺序、插入 encounter order 还是排序顺序，不能把三个概念混在一起。

## 44. Collection 和 Collections 有什么区别？

**面试回答**

`Collection` 是集合层次中的核心接口；`Collections` 是工具类，提供排序、查找、反转、不可修改视图、同步包装等静态方法。一个定义集合操作契约，一个提供通用算法和包装器。

**原理与理解**

例如 `Collections.synchronizedList` 返回带同步访问的包装视图，`Collections.unmodifiableList` 返回拒绝修改的视图；`List.sort` 和 `List.copyOf` 等现代 API 也承担了一部分常用任务。

**成立条件与边界**

同步包装不等于所有组合操作自动原子；遍历 synchronized 集合时通常仍需按文档在包装对象上同步。不可修改视图也不一定是独立快照，底层集合变化可能反映到视图中。

**实际场景（生产能力）**

暴露只读结果时先判断需要不可修改视图还是不可变副本；跨线程共享集合时明确锁覆盖范围，不能只包一层就默认复合逻辑安全。

**常见追问**

- synchronizedList 遍历还要加锁吗？（通常要在返回的包装对象上同步）
- unmodifiableList 与 copyOf 一样吗？（前者通常是视图，后者返回不可修改结果并有自己的空值规则）

**易错点**

只记“接口和工具类”不够，还要知道包装器的视图语义与组合操作边界。

## 45. ArrayList 和 LinkedList 有什么区别？

**面试回答**

ArrayList 是可变容量数组实现，按索引访问为常数时间、尾部追加为均摊常数时间；LinkedList 是双向链表实现，按索引要从较近一端遍历，但已定位节点或两端的插入删除只需调整链接。

**原理与理解**

ArrayList 元素引用集中存放，通常具有更好的缓存局部性和更低节点开销；LinkedList 每个元素有节点及前后链接。中间修改必须把“定位成本”和“修改动作”分开讨论。

**成立条件与边界**

“读多用 ArrayList、增删多用 LinkedList”过度简化。大量尾部追加仍适合 ArrayList；队列通常优先考虑 ArrayDeque；只有确实频繁在已知位置或两端修改时，LinkedList 才可能合适。

**实际场景（通用工程）**

查询结果和批量处理列表通常优先 ArrayList；需要 Deque 语义时先评估 ArrayDeque。关于中间插入见 [[04-集合#52. LinkedList 插入一定比 ArrayList 快吗？]]。

**常见追问**

- 两者都线程安全吗？（都不提供同步保证）
- ArrayList 如何增长？（见 [[04-集合#49. ArrayList 容量不足时会发生什么？]]）

**易错点**

复杂度不是实际性能的全部；节点分配、缓存局部性、元素数量和访问模式都会影响结果。

## 46. ArrayList 的底层数据结构是什么？

**面试回答**

ArrayList 的 API 定义它是 resizable-array，也就是可调整容量的数组实现。OpenJDK 使用对象引用数组保存元素；size 表示元素数量，capacity 表示内部数组可容纳数量，两者不能混同。

**原理与理解**

按索引读取数组位置，容量不足时分配更大存储并复制已有元素。`new ArrayList<>()` 的 API 描述初始容量为 10，而 OpenJDK 通常延迟到第一次添加时才分配默认数组。

**成立条件与边界**

`Object[] elementData`、懒分配和具体字段名是 OpenJDK 实现细节；API 只保证可增长以及追加的均摊常数时间，不保证内部字段和增长算法永久不变。

**实际场景（通用工程）**

已知将装入约一万条数据时，可通过构造容量或 `ensureCapacity` 降低渐进式重分配；但不要把容量直接设置为无依据的大值。

**常见追问**

- size 与 capacity 有何区别？（已有元素数与内部可容纳数）
- 容量不足如何处理？（见 [[04-集合#49. ArrayList 容量不足时会发生什么？]]）

**易错点**

“默认容量 10”不等于无参构造时立刻分配十个槽位；后者属于实现行为。

## 47. ArrayList 为什么随机访问快？

**面试回答**

ArrayList 实现 `RandomAccess`，按索引 `get/set` 为常数时间。因为内部以数组位置组织元素，不必像 LinkedList 一样沿节点逐个遍历。

**原理与理解**

数组能用索引直接定位槽位；RandomAccess 是标记接口，通用算法可据此选择索引遍历或迭代器遍历。LinkedList 的索引操作则从头或尾中较近的一端开始走链。

**成立条件与边界**

不要把 Java 语义写成“首地址 + i × 对象大小”。数组引用的物理布局、压缩指针和 JIT 优化由 JVM 决定；常数时间也不代表每次访问具有完全相同的硬件成本。

**实际场景（通用工程）**

需要频繁按下标读取、二分查找前后的列表处理通常选择 ArrayList；若只是顺序流式遍历，应同时考虑接口语义和整体数据规模。

**常见追问**

- RandomAccess 有方法吗？（没有，是标记接口）
- 常数时间是否等于绝对最快？（不是，只描述增长阶和典型访问路径）

**易错点**

回答“内存一定连续并直接算物理地址”把实现假设写成了 Java 保证。

## 48. ArrayList 为什么中间插入、删除较慢？

**面试回答**

在索引位置插入时，需要把该位置及之后的元素向右移动；删除时要向左移动后续元素并清空末尾槽位。因此工作量与移动的元素数量成正比，通常是 O(n)。

**原理与理解**

ArrayList 的 `add(index, e)` 明确会移动后续元素。末尾追加无需移动，在不扩容时很轻；尾部删除也无需搬移其他有效元素。

**成立条件与边界**

“O(n)”不等于一定比链表慢，数组复制可被高度优化且局部性好。若 LinkedList 只有索引而没有现成迭代器位置，它还要先付出 O(n) 定位成本。

**实际场景（通用工程）**

批量删除满足条件的元素优先考虑 `removeIf` 或一次过滤构建新列表，避免在前部反复删除造成多次大规模移动。

**常见追问**

- 尾部 add 的复杂度？（均摊 O(1)）
- set 会结构性修改吗？（替换元素，不改变 size，通常不属于结构性修改）

**易错点**

“ArrayList 增删都是 O(n)”遗漏了尾部操作和批量算法，应明确操作位置与是否扩容。

## 49. ArrayList 容量不足时会发生什么？

**面试回答**

实现会扩大内部容量，把已有元素复制到更大的存储后完成添加。ArrayList API 不规定增长倍数，只保证容量自动增长、追加具有均摊常数时间；OpenJDK 常见实现按约 1.5 倍方向增长，但这是版本实现细节。

**原理与理解**

扩容会产生新数组和复制成本，旧数组在不再被引用后才可回收。均摊分析把偶发的大复制分摊到多次 append 上，所以单次扩容仍可能形成延迟和内存峰值。

**成立条件与边界**

预设容量应根据预计元素数，而不是字节数；过大容量会浪费内存并可能影响 GC。API 允许增长策略变化，不能把 `old + old >> 1` 当跨 JDK 规范。

**实际场景（生产能力）**

批量查询已知结果上限时合理预估容量；不确定或数据可流式处理时，不为避免一次扩容而盲目申请超大数组。

**常见追问**

- 如何提前扩容？（构造器容量或 `ensureCapacity`）
- `trimToSize` 有何作用？（把容量收缩到当前 size 附近，但本身也有复制成本）

**易错点**

数组长度不能原地增加；“扩容 1.5 倍”必须标注 OpenJDK/版本边界。

## 50. ArrayList 是线程安全的吗？

**面试回答**

不是。多个线程并发访问同一 ArrayList，且至少一个线程做结构修改时，需要外部同步或选择合适并发集合。安全发布后的只读访问与并发修改是两种不同场景。

**原理与理解**

ArrayList 不为 size、数组替换和元素写入建立并发同步协议；并发 add/remove 可能丢更新、读取瞬态状态或抛异常。`Collections.synchronizedList` 使用互斥包装，CopyOnWriteArrayList 通过写时复制提供读多写少语义。

**成立条件与边界**

synchronizedList 的复合“检查再执行”仍需在同一锁内，遍历也要按文档同步。CopyOnWriteArrayList 写入复制整个数组，不适合写多或超大列表；Vector 仍可使用，但不代表复合操作自动原子。

**实际场景（生产能力）**

请求线程各自创建的局部 ArrayList 无需换并发集合；只有实例真正跨线程共享时，才根据读写比例、快照语义和原子操作要求选择方案。

**常见追问**

- 并发只读是否需要锁？（正确构造并安全发布后通常不因 ArrayList 自身而需要写锁）
- CopyOnWriteArrayList 适合什么？（读多写少、可接受快照迭代和写复制成本）

**易错点**

“线程不安全”不等于“任何多线程程序都不能用”，判断关键是同一实例是否共享并发生并发修改。

## 51. LinkedList 的底层数据结构是什么？

**面试回答**

LinkedList 是 List 与 Deque 的双向链表实现。节点保存元素以及前后链接；索引访问从头尾较近的一端遍历，两端操作可直接调整首尾节点。

**原理与理解**

双向链接支持 `addFirst/removeFirst/addLast/removeLast` 等操作，也支持 ListIterator 双向移动。代价是每个元素额外节点对象和链接字段，空间与缓存局部性通常不如数组。

**成立条件与边界**

LinkedList 允许 null，但若把它当 Queue 使用，null 会让 `poll` 返回值语义变得含糊；ArrayDeque 明确禁止 null，且常是队列/栈的优先选择。

**实际场景（通用工程）**

已持有 ListIterator 并频繁在当前位置插删时可考虑 LinkedList；普通 BFS/栈场景通常先用 ArrayDeque，再以测量决定。

**常见追问**

- LinkedList 能否随机访问？（能通过索引 API，但需要遍历）
- 为什么头尾操作快？（直接持有并调整首尾链接）

**易错点**

LinkedList 不是“增删快”的万能集合；节点定位和额外内存常被忽略。

## 52. LinkedList 插入一定比 ArrayList 快吗？

**面试回答**

不一定。若已通过 ListIterator 定位到节点，LinkedList 插入动作可以是 O(1)；若只给索引，中间位置需要 O(n) 遍历。ArrayList 定位为 O(1)，但要移动后续元素。实际快慢取决于位置、访问方式、规模和硬件局部性。

**原理与理解**

复杂度应拆为“找到位置”和“改变结构”。LinkedList 在两端或现有迭代器处有优势；ArrayList 的连续批量移动常由底层高效复制完成，且节点分配更少。

**成立条件与边界**

尾部追加两者都可以是 O(1)，ArrayList 是均摊；头部插入 ArrayList 需要移动。多次在同一区域插入时，保留 ListIterator 才能避免每次重新定位。

**实际场景（生产能力）**

在选结构前用真实操作序列做 JMH 基准，而不是用“链表改两个指针”直接得出生产结论。

**常见追问**

- 哪种情况 LinkedList 明确有优势？（已定位节点或频繁两端操作）
- 为什么 ArrayList 可能更快？（缓存局部性好、批量复制高效、节点更少）

**易错点**

只分析插入动作、不计算定位成本，是这道题最常见的逻辑缺口。

## 53. HashSet 为什么可以去重？

**面试回答**

HashSet 实现 Set 契约，并由 HashMap 支撑。添加元素时利用哈希缩小候选范围，再按 equals 语义判断是否已有等价元素；若已有，集合不发生变化，`add` 返回 false。

**原理与理解**

正确的 equals/hashCode 契约要求相等对象具有相同哈希值。哈希相同并不代表相等，仍要用 equals 区分；HashSet 也允许一个 null 元素。

**成立条件与边界**

自定义对象未正确实现 equals/hashCode，或入 Set 后修改了参与计算的字段，会出现“看似重复仍加入”或“已经存在却查不到”的问题。具体关系见 [[02-Object与String#20. 为什么重写 `equals()` 通常要重写 `hashCode()`？]]。

**实际场景（通用工程）**

对业务 ID 去重可直接使用 Set；对领域对象去重前先明确是按数据库主键、业务键还是全部字段相等，不能让代码生成器替代语义设计。

**常见追问**

- hashCode 相同就算重复吗？（不是，还要满足 equals）
- add 返回什么？（集合发生变化返回 true，已有等价元素返回 false）

**易错点**

HashSet 能执行既定相等规则，不会自动知道“业务上什么叫重复”。

## 54. HashSet 底层是怎么实现的？

**面试回答**

HashSet API 明确说明它由哈希表支撑，实际是 HashMap 实例。元素作为内部 Map 的 key；OpenJDK 使用共享占位对象作为 value，把查找、扩容和冲突处理委托给 HashMap。

**原理与理解**

`add(e)` 通过内部映射判断 key 是否原先存在，`contains/remove` 也转为 key 操作。HashSet 只向外暴露 Set 语义，隐藏无业务意义的 value。

**成立条件与边界**

“PRESENT 字段名”和具体调用代码是 OpenJDK 实现细节；调用方应依赖 Set API。HashSet 不保证迭代顺序，顺序甚至可能随扩容或版本变化。

**实际场景（通用工程）**

理解内部委托有助于联动 [[05-HashMap]] 的负载因子和迭代成本，但不能据此依赖节点布局或遍历顺序。

**常见追问**

- HashSet 与 HashMap 是继承关系吗？（不是，内部组合）
- HashSet 允许 null 吗？（允许一个 null 元素）

**易错点**

`HashSet.add` 返回的是“Set 是否变化”的 boolean，不是把 HashMap.put 的返回值原样暴露。

## 55. HashSet 和 HashMap 有什么关系？

**面试回答**

HashSet 内部组合一个 HashMap，以元素作为 key、占位对象作为 value，实现 Set 的唯一成员语义。它们不是继承关系，对外 API 和抽象职责也不同。

**原理与理解**

复用 HashMap 让 HashSet 获得预期常数时间的 add、remove、contains；其迭代成本还受 backing HashMap 的 capacity 与 size 共同影响。

**成立条件与边界**

HashSet 与 HashMap 都不提供同步保证并允许 null，但这只是当前实现契约的相似点；HashSet 不暴露 value，也不保证 Map 的所有行为都能从 Set API 观察到。

**实际场景（通用工程）**

需要成员关系和去重用 Set，需要 key-value 关联用 Map；不要为“底层一样”而用 Map 模拟所有 Set 业务。

**常见追问**

- 为什么是组合而不是继承？（HashSet 对外不是一种 Map）
- 初始容量过大有什么影响？（浪费空间，还会增加迭代空桶成本）

**易错点**

底层复用不代表抽象等价；面试要同时说清实现关系和 API 语义。

## 56. Iterator 是什么？

**面试回答**

Iterator 是顺序访问元素的统一接口，核心方法是 `hasNext`、`next`，并提供可选的 `remove` 和 `forEachRemaining`。它把遍历协议与集合内部结构分离。

**原理与理解**

对实现 Iterable 的集合，增强 for 通常获取 Iterator 并循环调用。Iterator 的 remove 删除最近一次 next 返回的元素，并且每次 next 后最多调用一次。

**成立条件与边界**

remove 是可选操作，默认实现会抛 `UnsupportedOperationException`；在 next 前或同一次 next 后调用两次会抛 `IllegalStateException`。迭代期间以其他方式修改底层集合时，通用 Iterator 契约可能未定义行为，具体集合可声明 fail-fast 或弱一致策略。

**实际场景（通用工程）**

需要在遍历中按条件删除时，先确认该迭代器支持 remove；相关异常见 [[04-集合#58. 什么是 ConcurrentModificationException？]]。

**常见追问**

- Iterator 能反向遍历吗？（普通 Iterator 不能，ListIterator 支持双向）
- next 到末尾会怎样？（抛 NoSuchElementException）

**易错点**

“Iterator.remove 永远安全可用”不成立，它可能不被实现支持，也有严格调用时序。

## 57. Iterator 和普通 for 循环有什么区别？

**面试回答**

索引 for 依赖按位置访问，主要适用于数组和 List；Iterator 依赖迭代协议，适用于实现 Iterable 的集合，不要求暴露索引。Map 本身不是 Iterable，通常迭代 `entrySet/keySet/values` 视图。

**原理与理解**

ArrayList 索引访问为常数时间，LinkedList 反复 `get(i)` 可能形成 O(n²)，使用 Iterator 顺序走链则是 O(n)。Iterator 还可能提供受控 remove；索引循环则需要自行管理位置变化。

**成立条件与边界**

增强 for 不适合所有修改需求；索引倒序删除、Iterator.remove、`removeIf` 或构建新集合各有语义。性能差异不能脱离具体实现和 JIT 测量。

**实际场景（通用工程）**

遍历 HashMap 优先 `for (var entry : map.entrySet())`，避免先遍历 key 再重复 get；LinkedList 顺序遍历不用索引 get。

**常见追问**

- Set 能用索引 for 吗？（不能，Set 不提供索引）
- List 正向删除如何避免漏项？（倒序、显式控制索引或使用受支持的迭代删除）

**易错点**

“删除后统一 i--”只是某些正向索引循环的技巧，不是通用遍历规则。

## 58. 什么是 ConcurrentModificationException？

**面试回答**

ConcurrentModificationException 表示某对象检测到不允许的并发或交错修改。典型 fail-fast 迭代器在创建后发现集合被非迭代器路径结构修改时可能抛出它；单线程也能触发。

**原理与理解**

ArrayList 等实现通常比较结构修改计数与迭代器期望值，尽早暴露错误用法。但 Java API 明确说明 fail-fast 只能 best-effort，非同步并发下无法保证一定检测到。

**成立条件与边界**

不能依赖“必定抛 CME”来实现并发正确性。某些并发集合使用弱一致或快照迭代器，不抛 CME；普通集合在未检测到时也不代表操作安全。

**实际场景（生产能力）**

发现 CME 时应排查集合所有权和修改路径，而不是 catch 后重试或忽略；并发场景要重新选择同步策略或数据结构。

**常见追问**

- 为什么名称有 Concurrent，但单线程也会抛？（并发指修改与迭代过程冲突，不限定不同线程）
- fail-fast 是安全保证吗？（不是，只是缺陷检测）

**易错点**

“modCount 不同就一定抛”是实现细节的过度承诺，规范明确只尽力检测。

## 59. 为什么 foreach 遍历集合时修改集合可能报错？

**面试回答**

对 Iterable 集合，增强 for 通常使用 Iterator。若循环中通过集合自身 add/remove 做结构修改，而迭代器策略不允许这种修改，后续操作可能抛 CME；也可能按具体迭代器契约表现为未定义、快照或弱一致结果。

**原理与理解**

普通 ArrayList/HashSet 的迭代器是 fail-fast；使用迭代器自身受支持的 remove 会同步维护迭代状态。`Collection.removeIf` 按集合实现提供的批量删除语义，未必都通过默认 Iterator 路径。

**成立条件与边界**

对元素调用 setter 通常不改变集合结构，但若元素是 HashSet 成员并改变了 equals/hashCode 字段，仍会破坏查找。CopyOnWriteArrayList 的快照迭代器不抛 CME，但其 remove 不受支持。

**实际场景（通用工程）**

单线程过滤优先 `removeIf` 或收集新列表；需要精确边遍历边删时使用支持 remove 的显式 Iterator；跨线程修改则设计同步或并发容器。

**常见追问**

- foreach 一定会抛 CME 吗？（不一定，取决于集合与是否被检测）
- 能否在 foreach 中修改对象字段？（通常可以，但要注意哈希/排序键不变量）

**易错点**

不是“任何修改都会报错”，关键是集合结构、迭代器策略和修改路径。

## 60. Comparable 和 Comparator 有什么区别？

**面试回答**

Comparable 由类型自身实现 `compareTo`，定义其自然顺序；Comparator 是外部比较策略，通过 `compare` 定义一种可替换顺序，并可用 `comparing`、`thenComparing`、`nullsFirst/nullsLast` 组合。

**原理与理解**

自然顺序适合类型长期稳定、普遍认可的排序；Comparator 适合按价格、时间、名称等多个业务维度排序。比较结果的符号表达小于、等于、大于，不应依赖固定返回 -1/0/1。

**成立条件与边界**

用于 TreeSet/TreeMap 时，比较结果为 0 会被视为同一排序位置；若排序与 equals 不一致，集合行为虽可能合法，却会违反一般 Set/Map 直觉。用 `a - b` 比较整数还可能溢出，应使用 `Integer.compare`。

**实际场景（通用工程）**

订单默认时间顺序可定义自然排序，页面临时按金额、状态、时间组合排序使用 Comparator，并显式处理 null 与稳定的次级排序键。

**常见追问**

- Comparator 能否有多个？（能，可按场景组合）
- 为什么 compare 为 0 很重要？（排序集合会据此判断键或元素等价）

**易错点**

只背“内部/外部排序”不够；必须知道比较契约、equals 一致性和整数减法溢出风险。
