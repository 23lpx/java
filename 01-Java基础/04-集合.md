# 集合

## 42. Java 常用集合有哪些？

**面试回答**

按接口分三类：List（有序可重复，如 ArrayList、LinkedList）、Set（无序不重复，如 HashSet、TreeSet）、Map（键值对，如 HashMap、TreeMap）。底层常用的还有 Queue（如 LinkedList 实现的双端队列）。

**理解**

集合框架顶层是 `Collection`（List、Set 的父接口）和 `Map`（独立体系）。List 关心顺序、允许重复；Set 关心唯一性；Map 存 key-value。开发中 ArrayList、HashMap、HashSet 用得最多。

**场景**

项目里返回菜品列表用 `List<Dish>`，去重用 `Set`，状态码映射用 `Map`，几乎每个接口都会用到这些集合。

**常见追问**

- Collection 和 Map 有关系吗？（没有继承关系，是两个独立体系）
- 线程安全的集合有哪些？（Vector、Hashtable、ConcurrentHashMap 等）

**易错点**

Map 不是 Collection 的子接口，它是独立的；别把「集合」只理解成 List。

## 43. List、Set、Map 有什么区别？

**面试回答**

List 有序、可重复，按索引访问；Set 无序、不可重复，保证元素唯一；Map 存键值对，key 唯一，通过 key 找 value。

**理解**

「有序」指按插入顺序（或排序顺序）存储。List 允许 null 和重复元素；Set 靠元素 equals/hashCode 保证不重复；Map 的 key 不能重复，value 可以。选择时：要顺序和重复用 List，要去重用 Set，要键值映射用 Map。

**场景**

项目里订单明细列表用 List（有顺序、可能重复），菜品口味标签去重用 Set，`Map<String, Object>` 存接口返回的键值数据。

**常见追问**

- Set 怎么保证不重复？（靠 hashCode + equals，见 [[04-集合#53. HashSet 为什么可以去重？]]）
- List 允许存 null 吗？（ArrayList 允许，LinkedList 也允许）

**易错点**

Set 的「无序」不是「随机」，只是不保证插入顺序；需要排序用 TreeSet，需要插入顺序用 LinkedHashSet。

## 44. Collection 和 Collections 有什么区别？

**面试回答**

Collection 是集合框架的顶层接口，List、Set 都实现它；Collections 是一个工具类，提供操作集合的静态方法，如排序、查找、同步包装。

**理解**

一个是接口（规范），一个是工具类（一堆静态方法）。`Collections.sort(list)` 排序、`Collections.reverse(list)` 反转、`Collections.synchronizedList(list)` 包装成线程安全列表，都是 Collections 提供的能力。命名很像但完全两回事。

**场景**

项目里要对 List 排序、打乱、求最值时，用 `Collections.sort(...)` 这类静态方法。

**常见追问**

- Collections 常用方法有哪些？（sort、reverse、shuffle、min、max、synchronizedXxx）
- Collection 下有哪些子接口？（List、Set、Queue）

**易错点**

Collection（接口）和 Collections（工具类）只差一个 s，面试口误很常见，注意区分。

## 45. ArrayList 和 LinkedList 有什么区别？

**面试回答**

ArrayList 底层是动态数组，随机访问快、中间插入删除慢；LinkedList 底层是双向链表，插入删除快（指针操作）、但随机访问慢（要遍历）。

**理解**

ArrayList 支持 O(1) 按下标访问，因为数组天然支持索引；LinkedList 要按位置访问得从头/尾遍历。ArrayList 中间插入删除要移动元素，LinkedList 只需改指针。所以「读多写少用 ArrayList，频繁头尾增删用 LinkedList」，但中间插入两者都不一定快（见 [[04-集合#52. LinkedList 插入一定比 ArrayList 快吗？]]）。

**场景**

项目里菜品列表、分页查询结果基本都用 ArrayList（读为主）；LinkedList 用于需要当队列/栈频繁在两端操作的场景（如用 Deque 做 BFS）。

**常见追问**

- 两者都线程安全吗？（都不安全）
- ArrayList 扩容机制？（见 [[04-集合#49. ArrayList 容量不足时会发生什么？]]）

**易错点**

「LinkedList 插入一定快」是错误结论，要结合位置和是否算上定位开销来判断。

## 46. ArrayList 的底层数据结构是什么？

**面试回答**

动态数组，底层是一个 `Object[] elementData`，可以根据元素数量自动扩容。

**理解**

ArrayList 内部维护一个 Object 数组，默认初始容量（JDK8 是 10，但懒加载，第一次 add 时才真正分配）。元素按顺序存在数组里，通过下标访问。数组存满后扩容，所以叫「动态数组」。

**场景**

`new ArrayList<>()` 后往里 add 菜品对象，底层就是不断往数组里放，满了自动扩容。

**常见追问**

- 初始容量多少？（默认 10，且是懒加载，第一次 add 才分配）
- 数组满了一定要扩容吗？（是，见 [[04-集合#49. ArrayList 容量不足时会发生什么？]]）

**易错点**

「默认容量 10」是 JDK8 的说法，且是懒加载；不同版本实现细节可能变，但「动态数组」这个本质不变。

## 47. ArrayList 为什么随机访问快？

**面试回答**

因为底层是数组，元素连续存储，通过下标能直接算出内存地址，O(1) 拿到元素，不需要遍历。

**理解**

数组元素在内存中连续排列，`get(i)` 就是「首地址 + i × 元素大小」，一次寻址即可。而 LinkedList 是链表，必须从头/尾沿着指针一个个找，是 O(n)。所以 ArrayList 支持高效随机访问，还实现了 `RandomAccess` 接口作为标记。

**场景**

项目里按索引遍历订单列表、随机取某个元素时，ArrayList 的 `get(i)` 是 O(1)，效率高。

**常见追问**

- RandomAccess 接口是干嘛的？（标记接口，表示支持快速随机访问，遍历时算法可据此优化）
- LinkedList 随机访问为什么慢？（要沿指针遍历）

**易错点**

ArrayList 随机访问快是因为「连续内存 + 下标寻址」，别只说「数组快」而不说原因。

## 48. ArrayList 为什么中间插入、删除较慢？

**面试回答**

因为数组元素连续存储，中间插入或删除一个元素，需要把它后面的所有元素整体向后或向前移动，平均要移动 n/2 个元素。

**理解**

在位置 i 插入时，i 到末尾的元素都要往后挪一格腾位置；删除时后面的元素要往前补位。这是 O(n) 的开销。而 LinkedList 只需改相邻节点的指针，是 O(1)（但定位到 i 本身还要遍历）。

**场景**

频繁在列表中间增删的场景，ArrayList 会有大量元素移动；如果只是末尾追加，ArrayList 很快（均摊 O(1)）。

**常见追问**

- 末尾插入慢吗？（不慢，均摊 O(1)，只有扩容时才搬数据）
- 为什么中间删除慢但末尾删除快？（末尾删不需要移动其他元素）

**易错点**

ArrayList「插入删除慢」主要指「中间位置」；末尾操作其实很快，别笼统说 ArrayList 增删都慢。

## 49. ArrayList 容量不足时会发生什么？

**面试回答**

会触发扩容：创建一个更大的新数组，把旧数组元素拷贝过去，再继续添加，旧数组被丢弃。

**理解**

JDK8 里扩容大小约为原来的 1.5 倍（`newCapacity = oldCapacity + oldCapacity >> 1`）。扩容涉及数组复制（`Arrays.copyOf`），有一定开销，所以如果预知元素数量，可以在 new 时指定容量（`new ArrayList<>(1000)`）减少多次扩容。

**场景**

项目里批量插入几千条订单明细时，如果提前知道数量，指定 ArrayList 初始容量能减少扩容次数、提高性能。

**常见追问**

- 扩容倍数是多少？（约 1.5 倍，JDK8）
- 为什么扩容有开销？（要复制整个数组）

**易错点**

扩容是「new 新数组 + 拷贝」，不是在原数组上直接加长（数组长度不可变）。

## 50. ArrayList 是线程安全的吗？

**面试回答**

不是。ArrayList 所有操作都没加锁，多线程并发读写会导致数据错乱或抛异常。

**理解**

ArrayList 底层数组操作不保证原子性，多线程同时 add 可能出现元素覆盖、size 计数错误，甚至数组越界。要线程安全可用 `Collections.synchronizedList(list)` 包装，或用 `CopyOnWriteArrayList`（读多写少场景），或直接用 Vector（性能差，已不推荐）。

**场景**

项目中普通业务（每个请求单线程处理）用 ArrayList 没问题；如果多个线程共享同一个 List 追加数据，就需要换成线程安全方案。

**常见追问**

- 怎么让 ArrayList 线程安全？（synchronizedList、CopyOnWriteArrayList）
- CopyOnWriteArrayList 原理？（写时复制，读不加锁，写时复制新数组）

**易错点**

ArrayList 线程不安全不等于「用了一定出错」，单线程或线程隔离场景下完全没问题，关键是「多线程共享同一实例」。

## 51. LinkedList 的底层数据结构是什么？

**面试回答**

双向链表，每个节点保存数据和前驱、后继两个指针，LinkedList 同时持有头尾节点的引用。

**理解**

每个 Node 有 `item`（数据）、`prev`（前一个节点）、`next`（后一个节点）。因为持有头尾引用，所以在头部和尾部插入删除都是 O(1)。它还实现了 `Deque` 接口，可以当队列或栈用。

**场景**

项目里需要「先进先出」或「后进先出」时，用 LinkedList 作为队列/栈（如 BFS 用队列）。

**常见追问**

- LinkedList 为什么头尾操作快？（持有头尾节点引用，直接改指针）
- LinkedList 能随机访问吗？（能，但要遍历，慢）

**易错点**

LinkedList 是「双向」链表，不是单向；它头尾操作快，但中间定位慢。

## 52. LinkedList 插入一定比 ArrayList 快吗？

**面试回答**

不一定。LinkedList 在头部、尾部插入确实快（O(1)），但中间插入需要先遍历定位到该位置，定位是 O(n)；而 ArrayList 中间插入要移动元素但定位是 O(1)。所以中间插入谁快取决于数据量和位置，不能一概而论。

**理解**

这个结论要拆成「定位」和「插入」两步。LinkedList 插入动作本身 O(1)（改指针），但走到中间节点要 O(n) 遍历；ArrayList 定位 O(1)，但插入要 O(n) 移动元素。所以：头部插 LinkedList 快，尾部插两者都快（ArrayList 均摊 O(1)），中间插在小数据量下 LinkedList 可能稍快、大数据量下两者接近或 ArrayList 更快（缓存友好）。

**场景**

这是典型的「纠正绝对化结论」的题。面试被问「LinkedList 插入一定比 ArrayList 快吗」时，回答「不一定，要看位置」，并解释定位开销。

**常见追问**

- 那 LinkedList 到底擅长什么？（头部/尾部插入删除，做队列栈）
- 为什么 ArrayList 移动元素反而可能不慢？（数组连续内存，缓存友好）

**易错点**

「LinkedList 插入一定快」是经典错误，务必强调「中间插入要先定位」。

## 53. HashSet 为什么可以去重？

**面试回答**

HashSet 内部靠 HashMap 实现，元素作为 key 存入，利用 HashMap 的 key 唯一性（通过 hashCode + equals 判断）来保证不重复。

**理解**

HashSet 添加元素时，把元素当作 HashMap 的 key，value 是一个固定的占位对象。HashMap 判断 key 是否已存在：先比 hashCode 定位桶，再用 equals 比较。所以只要元素的 hashCode 和 equals 正确，重复元素就加不进去。

**场景**

项目里对菜品标签、id 列表去重时，直接把 List 转成 HashSet 就能去重。

**常见追问**

- 自定义对象放 HashSet 去重要注意什么？（重写 hashCode 和 equals，见 [[02-Object与String#20. 为什么重写 `equals()` 通常要重写 `hashCode()`？]]）
- 为什么 HashSet 无序？（底层 HashMap 的存储顺序和 hashCode 有关）

**易错点**

HashSet 去重依赖 hashCode + equals，自定义对象不重写这两个方法，去重会失效。

## 54. HashSet 底层是怎么实现的？

**面试回答**

HashSet 底层就是一个 HashMap，元素存在 HashMap 的 key 里，value 统一是一个名为 PRESENT 的静态占位对象。

**理解**

`new HashSet<>()` 内部实际 `new HashMap<>()`，`add(e)` 就是 `map.put(e, PRESENT)`。判断重复、存储位置、扩容全都由 HashMap 完成，HashSet 只是对 HashMap 的一层封装，屏蔽了 value 这个无关概念。

**场景**

理解这一点后，HashSet 的去重、扩容、无序等特性都能用 [[05-HashMap]] 的知识解释。

**常见追问**

- HashSet 的 value 存什么？（统一的 PRESENT 占位对象）
- HashSet 的 add 返回什么含义？（返回 map.put 的结果，false 表示元素已存在）

**易错点**

HashSet 不是「数组实现的」，它复用 HashMap，别把 Set 和数组扯上关系。

## 55. HashSet 和 HashMap 有什么关系？

**面试回答**

HashSet 是 HashMap 的封装：HashSet 把元素作为 HashMap 的 key 存储，value 用固定占位对象，复用 HashMap 的 key 唯一性实现去重。

**理解**

二者是「组合/委托」关系，不是继承关系。HashSet 内部持有一个 HashMap 字段，所有操作都转给 HashMap。所以 HashMap 的特性（基于 hash、无序、key 唯一、可存 null）HashSet 基本都有。

**场景**

面试问 HashSet 原理时，直接说「底层是 HashMap」就能覆盖去重、无序、扩容等一连串问题。

**常见追问**

- HashSet 能存 null 吗？（能，因为 HashMap 允许 null key）
- HashSet 和 HashMap 是继承关系吗？（不是，是组合，HashSet 内嵌 HashMap）

**易错点**

是「组合」不是「继承」，HashSet 没有继承 HashMap，而是内部持有它。

## 56. Iterator 是什么？

**面试回答**

Iterator 是集合的迭代器接口，提供统一的遍历方式：`hasNext()` 判断有没有下一个，`next()` 取下一个元素，`remove()` 在遍历中安全删除当前元素。

**理解**

它把「遍历」从具体集合实现中抽离出来，不管底层是数组还是链表，都能用同一套方法遍历。配合 foreach 语法糖，Java 会自动调用 Iterator。它的一个重要能力是遍历中通过 `iterator.remove()` 安全删除元素，避免并发修改异常。

**场景**

项目里遍历 List 并删除某些元素时，用 Iterator 的 remove，而不是 foreach 里直接 `list.remove()`（会抛异常，见 [[04-集合#58. 什么是 ConcurrentModificationException？]]）。

**常见追问**

- foreach 底层是 Iterator 吗？（是，编译后转成 Iterator 遍历）
- Iterator 能逆向遍历吗？（普通 Iterator 不能，ListIterator 可以）

**易错点**

遍历中删除要用 `iterator.remove()`，不能用集合的 `remove()`，否则抛 ConcurrentModificationException。

## 57. Iterator 和普通 for 循环有什么区别？

**面试回答**

普通 for 循环靠索引访问，只适合 List 这类有序集合；Iterator 不依赖索引，所有 Collection 都能用，而且支持遍历中安全删除。

**理解**

`for (int i...)` 只能用下标，Set、Map 没有下标就用不了；Iterator 是统一的遍历接口，任何集合都能遍历。另外，Iterator 的 `remove()` 能在遍历中安全删除当前元素，普通 for 循环删除要自己处理索引回退，容易漏删或越界。

**场景**

项目里遍历 Set 只能用 Iterator/foreach；遍历 List 删除元素时，用 Iterator 更安全。

**常见追问**

- 遍历 List 删除元素，普通 for 循环怎么处理？（删除后 i-- 回退，否则漏删）
- 两者性能有差别吗？（ArrayList 用索引 for 稍快，LinkedList 用 Iterator 快）

**易错点**

普通 for 循环删除 List 元素要手动 i--，否则会跳过下一个元素。

## 58. 什么是 ConcurrentModificationException？

**面试回答**

遍历集合过程中，集合结构被修改（不是通过迭代器自己的 remove），迭代器检测到修改次数变化，就会抛出这个异常，属于 fail-fast 机制。

**理解**

集合内部有个 `modCount` 记录结构修改次数，Iterator 创建时记下当时的 `modCount`，每次 `next()` 时比对，不一致就抛异常。它用来尽早暴露「遍历中修改集合」的隐患，避免出现不可预期的数据问题。单线程和多线程下都可能触发。

**场景**

foreach 遍历 List 时直接 `list.remove(obj)`，第二次 next 就会抛 ConcurrentModificationException。

**常见追问**

- 怎么避免？（用 iterator.remove，或改用普通 for 循环，或遍历完再删）
- fail-fast 和 fail-safe 区别？（fail-fast 直接抛异常，fail-safe 如 CopyOnWriteArrayList 在副本上遍历）

**易错点**

这个异常不是多线程特有的，单线程 foreach 里删元素同样会抛，别把它理解成「并发」才有的问题。

## 59. 为什么 foreach 遍历集合时修改集合可能报错？

**面试回答**

因为 foreach 底层是 Iterator，遍历中用集合自己的 add/remove 修改结构，会让 modCount 变化，迭代器 next 时发现不一致，抛出 ConcurrentModificationException。

**理解**

foreach 编译后是 `Iterator` + `hasNext()/next()`。如果你在循环体里调 `list.remove()`，改的是集合的 modCount，而迭代器保存的还是旧值，下次 next 校验就失败。正确做法是用 `iterator.remove()`，它会同步更新 modCount。

**场景**

项目里要删除列表中某些满足条件的元素时，应该用 `Iterator` 的 remove，或改用 `removeIf`（Java 8），不要在 foreach 里直接删。

**常见追问**

- 除了 ConcurrentModificationException 还会有什么问题？（用普通 for 可能漏删）
- removeIf 为什么安全？（内部用 Iterator 实现）

**易错点**

遍历中「修改」包括 add 和 remove，都会触发；只有通过迭代器自身的 remove 才安全。

## 60. Comparable 和 Comparator 有什么区别？

**面试回答**

Comparable 是「内部排序」，类自己实现 `compareTo` 方法定义自然顺序；Comparator 是「外部排序」，单独写比较器实现 `compare` 方法，可定义多种排序规则。

**理解**

Comparable 侵入类本身，一个类只能有一种自然顺序（如按 id 升序）；Comparator 是独立比较器，不改原类，想按哪个字段排就写几个比较器，更灵活。`Collections.sort(list)` 用 Comparable，`sort(list, comparator)` 用 Comparator。

**场景**

项目里对菜品列表排序：默认按 id（实体实现 Comparable），临时按销量、价格排序时传不同的 Comparator（或用 `Comparator.comparing(Dish::getPrice)`）。

**常见追问**

- 两者怎么用？（Comparable 实现 compareTo，Comparator 实现 compare 或 lambda）
- Java 8 怎么简化 Comparator？（Comparator.comparing 方法引用）

**易错点**

Comparable 是「类内部实现」，Comparator 是「外部传入」，别把方向搞反；一个类只能有一个 Comparable 的自然序，但可以有多个 Comparator。
