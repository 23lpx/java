# 面向对象

## 1. Java 面向对象的三大特性是什么？

**面试回答**

封装、继承、多态。封装是隐藏内部细节、只暴露接口；继承是子类复用父类的属性和方法；多态是同一个方法调用，实际执行的是子类的实现。

**理解**

封装通过 `private` 字段 + `getter/setter` 实现，让外部不能随意改内部状态；继承让子类复用父类代码，形成「is-a」关系；多态靠「父类引用指向子类对象」实现，运行时才决定调谁的方法。这三点是面向对象思想的核心，Java 语言层面都直接支持。

**场景**

外卖项目里每个实体类（菜品 Dish、订单 Order、地址 AddressBook）都用 `private` 字段封装；Service 接口 + `ServiceImpl` 实现类体现多态，调用方只依赖接口。

**常见追问**

- 多态是怎么实现的？（父类引用 + 动态绑定）
- 三大特性有什么好处？（可维护、可扩展、可复用）

**易错点**

「抽象」常被说成第四大特性，面试问三大特性时先说清封装、继承、多态，抽象可以补充提。

## 2. 封装、继承、多态分别是什么？

**面试回答**

封装是把数据和操作数据的方法包在一起，用访问修饰符控制可见性；继承是子类获得父类的字段和方法；多态是同一类型的不同对象对同一方法有不同表现。

**理解**

封装强调「信息隐藏」，对象内部状态只能通过规定的方法访问，降低耦合；继承强调「复用和层次」，但过度继承会耦合过紧，所以现在更推荐「组合优于继承」；多态强调「可替换性」，调用方写父类类型，运行时由具体子类决定行为，这是能写出可扩展代码的关键。

**场景**

项目里 DTO、VO、Entity 字段都 `private` 封装；`BaseContext`/通用父类被多个实体继承公共字段（如 `id`、`createTime`）；Service 层面向接口编程体现多态。

**常见追问**

- 封装的作用？（保护数据、便于修改内部实现）
- 多态的好处？（代码更灵活，新增子类不用改调用方）

**易错点**

多态不是重载，重载是编译期决定、多态是运行期决定，别把二者混为一谈。

## 3. 什么是方法重载？什么是方法重写？

**面试回答**

重载是同一个类里方法名相同、参数列表不同（个数、类型或顺序不同）；重写是子类重新实现父类已有的方法，方法签名一致。

**理解**

重载发生在同一个类内，靠参数列表区分，和返回值无关，是「编译期多态」；重写发生在父子类之间，子类用相同签名覆盖父类实现，是「运行期多态」，加 `@Override` 注解让编译器帮我们校验是否真的重写。

**场景**

实体类的多个构造器就是重载（无参构造、全参构造）；`ServiceImpl` 里 `@Override` 实现 `Service` 接口/父类的方法就是重写。

**常见追问**

- 重载能只靠返回值区分吗？（不能）
- 重写对访问权限有什么要求？（子类不能比父类更严格）

**易错点**

重载跟返回类型无关，两个方法只有返回值不同不构成重载，编译会报错。

## 4. 重载和重写有什么区别？

**面试回答**

重载是同一个类里同名不同参，重写是子类对父类同名同参方法重新实现；重载看参数列表、是编译期行为，重写看方法签名、是运行期多态。

**理解**

区别主要四点：发生位置（同类 vs 父子类）、参数列表（必须不同 vs 必须相同）、返回值（重载可不同，重写返回类型必须兼容）、访问修饰符（重载没限制，重写不能收窄）。核心一句话：重载是「同名方法不同参数」，重写是「子类覆盖父类方法」。

**场景**

详见 [[01-面向对象#3. 什么是方法重载？什么是方法重写？]]，这里不重复。

**常见追问**

- 重写时返回值必须完全一样吗？（基本类型必须一致，引用类型可以返回子类型，即协变返回）
- `static` 方法能被重写吗？（不能，静态方法属于类，不存在运行期多态）

**易错点**

重写要求方法签名完全一致，但返回类型允许「协变」——子类返回父类返回值的子类型，这是合法重写，别一刀切说「返回值必须相同」。

## 5. 接口和抽象类有什么区别？

**面试回答**

接口是一种「能做什么」的规范，抽象类是「是什么」的模板。接口可以多实现、不能实例化、没有构造器；抽象类也不能实例化、有构造器、单继承。Java 8 之后接口可以有 `default` 和 `static` 方法。

**理解**

两者都是抽象层次，但设计意图不同：接口强调能力约定（多个无关类可以有共同能力），抽象类强调公共实现的复用（共享字段和已实现方法）。接口里字段默认 `public static final`，抽象类可以有普通字段和构造方法。单继承限制下，要扩展多种能力通常靠接口。

**场景**

项目里 `Mapper` 接口、`Service` 接口都是接口，只定义方法签名，由 MyBatis 动态代理或 `ServiceImpl` 实现；如果多个实体有完全相同的公共字段和逻辑，才考虑抽一个抽象基类，否则优先用接口。

**常见追问**

- 什么时候用接口、什么时候用抽象类？（要多种能力用接口，要共享实现用抽象类）
- 接口的 `default` 方法是什么？（给接口提供默认实现，不破坏已有实现类）

**易错点**

Java 8 前说「接口不能有方法体」是对的，Java 8 后接口可以有 `default`/`static` 方法，回答时要带上版本前提，否则会被追问打脸。

## 6. Java 为什么不支持类的多继承？

**面试回答**

为了避免「菱形继承」问题：如果一个类同时继承两个有相同方法签名的父类，调用时就不知道该执行哪个，会产生歧义。

**理解**

C++ 支持多继承，但会带来菱形问题和复杂度。Java 用「单继承类 + 多实现接口」折中：类只能单继承，但可以实现多个接口。接口在 Java 8 前只有方法声明没有实现，即使两个接口有同名方法也没有冲突；Java 8 引入 `default` 方法后，如果多个接口的 `default` 方法签名冲突，实现类必须自己重写来消除歧义。

**场景**

项目里一个 `ServiceImpl` 只继承一个父类，但可以同时 `implements` 多个接口（比如某个 Service 既要缓存能力又要日志能力时用不同接口组合）。

**常见追问**

- 接口能多继承吗？（接口之间可以 `extends` 多个接口）
- 那接口的 default 方法冲突怎么解决？（实现类必须重写）

**易错点**

「接口多实现」不等于「类多继承」，别把两者说成一回事；接口之间才是真的可以多继承。

## 7. 一个类可以实现多个接口吗？

**面试回答**

可以。一个类用 `implements` 实现多个接口，从而同时获得多种能力，这是 Java 弥补单继承限制的主要手段。

**理解**

接口只约定方法（Java 8 前的纯抽象方法），没有状态和实现冲突，所以多实现不会带来多继承的菱形问题。实现类必须实现所有接口的抽象方法，除非它是抽象类。Java 8 后多个接口若有签名相同的 `default` 方法，实现类要重写该方法。

**场景**

项目里实体类可以实现 `Serializable`（可序列化）等标记接口，Service 类可以同时实现业务接口和某个通用能力接口，灵活组合。

**常见追问**

- 实现多个接口后需要实现所有方法吗？（是，除非类本身是 abstract）
- 接口和抽象类在「多继承」上差别是什么？（类只能单继承、接口可以多实现/多继承）

**易错点**

接口里没有实现的方法必须在实现类里全部实现，遗漏任何一个编译就报错。

## 8. `this` 和 `super` 有什么区别？

**面试回答**

`this` 指当前对象，用来访问本类的字段、方法、构造器；`super` 指父类，用来访问父类的字段、方法、构造器。

**理解**

`this` 解决「局部变量和成员变量同名」时的遮蔽问题（`this.name = name`）；`super` 在子类需要调用被重写的父类方法，或调用父类构造器时使用。构造器里 `this(...)` 或 `super(...)` 必须是第一条语句，且二者只能出现一个。

**场景**

实体类构造器里 `super()` 调用父类构造，Service 实现类里 `this.xxx()` 调用本类其他方法；子类重写方法时可能先 `super.method()` 复用父类逻辑。

**常见追问**

- `this()` 和 `super()` 能同时出现在构造器里吗？（不能）
- `super` 是一个对象引用吗？（不是，是特殊关键字，只是用来定位父类成员）

**易错点**

`super` 不是「父类对象」的引用，它只是编译器用来指向父类成员的关键字；别把它当普通引用变量用。

## 9. `static` 修饰变量、方法分别有什么特点？

**面试回答**

`static` 修饰的变量和方法属于类本身，而不是某个实例，所有实例共享，可以直接用「类名.」调用，不需要创建对象。

**理解**

静态变量在类加载时初始化一次，被所有对象共享；静态方法只能访问静态成员，不能访问实例变量和方法，因为没有 `this`。静态成员和对象生命周期不同，静态成员随类加载而存在，随类卸载而消失。

**场景**

项目里工具类方法、常量（如订单状态常量 `ORDER_STATUS_PAID`）、`BaseContext` 这类用 `static` 保存线程上下文的地方都用了 `static`。

**常见追问**

- 静态方法能访问实例变量吗？（不能，没有 this）
- 静态方法能被重写吗？（不能，见 [[01-面向对象#4. 重载和重写有什么区别？]]）

**易错点**

静态方法里不能直接用 `this`、不能访问实例字段；「静态方法可以被继承但不能被重写」，实际调用时看引用类型而非对象类型。

## 10. `final` 可以修饰哪些内容？分别有什么作用？

**面试回答**

`final` 可以修饰类、方法、变量：修饰类不能被继承，修饰方法不能被重写，修饰变量一旦赋值不能改。

**理解**

修饰基本类型变量是「值不可变」；修饰引用类型变量是「引用不可变」，即不能再指向别的对象，但对象内部的内容仍然可以改。`final` 常用来定义常量（`final` + `static`）、防止方法被子类改坏、防止类被恶意继承。

**场景**

项目里常量用 `static final`（如支付回调里 RSA 公钥、订单状态枚举值）；`String` 类本身就是 `final`，所以不可被继承。

**常见追问**

- `final` 修饰引用类型，对象内容能改吗？（能，只是引用不能再指向别处）
- `final` 变量一定要在声明时赋值吗？（不一定，可在构造器里赋值，但每个构造器都要赋值）

**易错点**

「final 变量不可变」要分情况：基本类型是值不变，引用类型是引用不变、对象内容可变，别一刀切。

## 11. Java 是值传递还是引用传递？

**面试回答**

Java 只有值传递。基本类型传的是值的副本，引用类型传的是「引用的副本」，也就是地址值的拷贝。

**理解**

方法里对基本类型参数修改不影响外部变量；对引用类型参数，通过这个副本引用去修改对象内容会影响外部（因为指向同一个对象），但如果在方法里给参数重新赋值、让它指向新对象，不会影响外部的原引用。这正是「值传递」的关键：传进去的是引用的拷贝，不是引用本身。

**场景**

订单 Service 里把 `Order` 对象传给方法，方法里 `order.setStatus(...)` 会影响外部对象；但方法里 `order = new Order()` 则不会影响调用方的引用。

**常见追问**

- 为什么引用类型「看起来像」引用传递？（因为通过拷贝引用能改到同一对象）
- 如何证明 Java 是值传递？（方法里给参数重新赋值，外部引用不变）

**易错点**

Java 常被误说成「引用传递」，准确说法是「值传递，其中引用类型传的是引用的副本」；面试追问时容易在这里翻车。

## 12. 成员变量和局部变量有什么区别？

**面试回答**

成员变量定义在类里、方法外，属于对象，有默认值；局部变量定义在方法或代码块里，没有默认值，必须显式初始化后才能用。

**理解**

成员变量随对象创建而分配、随对象回收而回收，基本类型有默认值（如 int 是 0、boolean 是 false），引用类型默认 null；局部变量在方法调用时入栈，方法结束出栈，作用域只在定义它的块内，使用前必须赋值。成员变量还有默认的访问修饰符，局部变量不能加 `public/private` 等。

**场景**

实体类字段是成员变量（`private Long id;` 默认 null），Service 方法里的 `List<Dish> list` 是局部变量，必须初始化才能用。

**常见追问**

- 成员变量默认值分别是多少？（int 0、boolean false、引用 null 等）
- 成员变量和局部变量能重名吗？（能，方法内优先用局部变量，可用 this 区分）

**易错点**

局部变量没有默认值，未初始化就使用会编译报错，这是新手常犯的错。

## 13. 基本数据类型和引用数据类型有什么区别？

**面试回答**

基本类型直接存值，引用类型存的是对象的地址（引用）；基本类型有默认值、不能为 null，引用类型默认是 null。

**理解**

基本类型变量在栈上直接保存数值；引用类型变量在栈上保存地址，实际对象存在堆里。基本类型之间用 `==` 比的是值，引用类型用 `==` 比的是地址是否相同，要比较内容得用 `equals`（详见 [[02-Object与String]]）。基本类型占用固定大小内存，引用类型大小不固定。

**场景**

订单金额、数量等数值在计算时涉及基本类型；实体对象、集合、数组都是引用类型。

**常见追问**

- `==` 对两种类型分别比什么？（基本类型比值，引用类型比地址）
- 基本类型对应的包装类是什么？（见 [[01-面向对象#14. Java 有哪些基本数据类型？]]）

**易错点**

`null` 只能赋给引用类型，基本类型不能为 null；引用类型用 `==` 比较的是地址不是内容。

## 14. Java 有哪些基本数据类型？

**面试回答**

8 种：`byte`、`short`、`int`、`long`、`float`、`double`、`char`、`boolean`。

**理解**

四个整数类型范围递增（byte 1 字节、short 2、int 4、long 8），`float`（4 字节）和 `double`（8 字节）是浮点类型，`char` 是单个字符，`boolean` 只有 true/false。`long` 字面量加 `L`，`float` 字面量加 `F`。默认整数是 int，默认小数是 double。

**场景**

订单金额用 `BigDecimal` 而不是 `double`，因为 `double` 有精度丢失问题（0.1 + 0.2 != 0.3），金额计算必须精确。

**常见追问**

- 为什么金额不用 double？（精度丢失，用 BigDecimal）
- 各类型占多少字节？（byte 1、short 2、int 4、long 8、float 4、double 8、char 2、boolean 看情况）

**易错点**

`String` 不是基本类型，是引用类型；`boolean` 占多少字节没有严格规定，别背成固定值。

## 15. 自动装箱和拆箱是什么？

**面试回答**

装箱是基本类型自动转成包装类（`int` → `Integer`），拆箱是包装类自动转成基本类型（`Integer` → `int`），由编译器自动完成。

**理解**

装箱实际调 `Integer.valueOf(int)`，拆箱调 `intValue()`。它让基本类型和包装类能混用，尤其是集合只能存对象，`List<Integer>` 存 int 时就会自动装箱。拆箱时如果包装类是 null，会抛 `NullPointerException`。

**场景**

项目里 `List<Integer> ids` 存订单 id，add 一个 int 会自动装箱；`Integer status = order.getStatus()` 后做 `status == 1` 比较时会自动拆箱，但 status 为 null 会 NPE。

**常见追问**

- 装箱拆箱有什么性能问题？（频繁装箱会产生额外对象，循环里大量装箱有开销）
- 装箱时 `Integer.valueOf` 会复用缓存吗？（-128~127 复用，见 [[01-面向对象#17. Integer 缓存是什么？]]）

**易错点**

自动拆箱遇到 null 会 NPE，`Integer` 与 `int` 混用时最容易踩。

## 16. Integer 和 int 有什么区别？

**面试回答**

`int` 是基本类型，`Integer` 是它的包装类。int 默认值是 0，Integer 默认值是 null；int 不能为 null、没有方法，Integer 是对象、有各种方法。

**理解**

Integer 除了存一个 int 值，还提供很多工具方法（如 `parseInt`、`valueOf`）。在集合、泛型里必须用 Integer，因为泛型不支持基本类型；而 DTO/VO 里字段用 Integer 而不是 int，是为了区分「没传值(null)」和「传了 0」这两种情况。Integer 比 int 多一个对象头，占用更多内存。

**场景**

项目里订单状态、数量等 DTO 字段用 Integer：比如「是否删除」字段用 Integer 而不是 int，就能表达「未设置」这个状态（null），而 int 只能是 0/1。

**常见追问**

- 为什么 DTO 里用 Integer 不用 int？（区分 null 和 0，配合参数校验）
- Integer 和 int 能直接比较吗？（能，会自动拆箱，但要注意 null）

**易错点**

Integer 默认 null，int 默认 0；在数据库映射时字段可为空就要用 Integer，否则空值会出问题。

## 17. Integer 缓存是什么？

**面试回答**

Integer 在装箱时对 -128 到 127 之间的值做了缓存，这个范围内用 `==` 比较两个 Integer 会相等，范围外则不等。

**理解**

`Integer.valueOf(int)` 会先查缓存，-128~127 命中就直接返回缓存对象，所以 `Integer a = 100; Integer b = 100;` 里 a 和 b 指向同一对象，`a == b` 为 true；而 128 超出范围，会 new 新对象，`a == b` 为 false。所以比较 Integer 的值应该用 `equals` 而不是 `==`。

**场景**

订单状态码、菜品分类 id 等小整数如果拆成 Integer 对象，在缓存范围内 `==` 可能「碰巧」相等，范围外又不等，所以统一用 `equals` 比较最安全。

**常见追问**

- 缓存范围能改吗？（上限可通过 `-XX:AutoBoxCacheMax` 调整，但实习面试知道默认 -128~127 即可）
- 为什么不缓存所有值？（缓存太多对象占内存，权衡后只缓存常用小整数）

**易错点**

`==` 比较两个 Integer 是比地址，受缓存影响结果不稳定，比较数值一律用 `equals`。
