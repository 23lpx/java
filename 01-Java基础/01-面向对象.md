# 面向对象

## 1. Java 面向对象的三大特性是什么？

**面试回答**

通常概括为封装、继承和多态。封装负责隐藏实现并维护对象约束；继承表达可替换的类型关系和代码复用；多态让同一父类型引用在运行时表现出不同实现。“三大特性”是教学归纳，不是 Java 语言规范中的正式分类。

**原理与理解**

面向对象的重点不是把代码放进类里，而是让对象对自己的状态和行为负责。Java 通过访问控制、类继承、接口实现、方法重写和动态分派支持这些能力。

**成立条件与边界**

继承不是复用的唯一方式，组合通常耦合更低；多态主要讨论可重写的实例方法，字段访问、静态方法和私有方法不能按同样方式理解。

**实际场景（通用工程）**

支付服务可以依赖 `PaymentStrategy` 接口，由微信、支付宝实现类提供不同扣款行为；调用方只依赖抽象，通过多态选择实现。

**常见追问**

- 三者分别解决什么问题？（约束状态、建立类型关系、替换实现）
- 多态的必要条件是什么？（存在父子类型关系、方法重写，并通过父类型引用调用实例方法）

**易错点**

不要把“封装=字段全设为 private”“继承=复制父类代码”“多态=方法重载”当成完整定义。

## 2. 封装、继承、多态分别是什么？

**面试回答**

封装是通过清晰边界控制状态的读取和修改，保护不变量；继承是子类获得父类可继承成员并形成子类型关系；多态是同一父类型或接口引用可以指向不同实现，实例方法调用在运行时动态选择实际实现。

**原理与理解**

封装强调“对象如何保证自己始终合法”，不等于机械生成 getter/setter。继承建立 `is-a` 关系；多态则让调用方依赖稳定抽象，而把变化留给实现类。

**成立条件与边界**

若子类无法满足父类型约定，就不应为了复用而继承。组合表达 `has-a` 关系，常比深层继承更易维护；开放 setter 也可能破坏封装。

**实际场景（通用工程）**

订单状态只能通过 `pay()`、`cancel()` 等业务方法迁移，而不是暴露任意 `setStatus()`；通知渠道实现统一接口，业务层不用写大量渠道判断。

**常见追问**

- 封装为什么不等于 private？（private 只是手段，目标是维护边界和不变量）
- 继承与组合如何选择？（稳定的可替换类型关系用继承，能力拼装和复用优先考虑组合）

**易错点**

“父类引用指向子类对象”只是多态的使用形式之一，核心是对抽象编程和实例方法的动态分派。

## 3. 什么是方法重载？什么是方法重写？

**面试回答**

重载是在同一类或继承成员集合中出现同名、但形参列表不同的方法，由编译器在编译期选择；重写是子类为继承到的实例方法提供满足规则的新实现，运行时根据对象实际类型分派。

**原理与理解**

重载解析会考虑方法名、参数数量、参数类型以及适用的转换；返回类型不能单独区分重载。重写要求方法签名满足覆盖关系，并受访问级别、返回类型和受检异常等约束。

**成立条件与边界**

静态方法只能隐藏，不能重写；private 方法不被子类继承，final 方法不能重写。重写可以使用协变返回类型，访问权限不能更严格，抛出的受检异常不能比父方法更宽。

**实际场景（通用工程）**

`send(String)` 与 `send(String, Duration)` 是重载；不同通知实现覆盖接口的 `send(Message)` 是重写。可结合 [[01-面向对象#4. 重载和重写有什么区别？]] 记忆。

**常见追问**

- 仅返回值不同能否重载？（不能）
- 静态方法是否参与运行时多态？（不参与，按引用的编译期类型选择）

**易错点**

不要用“同一类内才叫重载”作为绝对定义，继承来的同名方法也可能与当前声明共同构成重载集合。

## 4. 重载和重写有什么区别？

**面试回答**

重载解决“同一操作支持不同参数”，在编译期根据实参选择；重写解决“子类型替换父类型实现”，对实例方法在运行时动态分派。重载看参数列表，重写看继承关系和覆盖规则。

**原理与理解**

重载属于静态选择：编译器从候选方法中选最具体的适用方法。重写属于动态选择：编译后调用的签名已确定，运行时再按接收对象实际类型找到实现。

**成立条件与边界**

重载允许不同返回类型，但不能只靠返回类型区分；重写返回类型必须相同或协变。重载与 static、private、final 不冲突；重写受这些修饰符限制。

**实际场景（通用工程）**

Controller 提供不同参数组合的转换工具可使用重载；策略接口由多个实现类重写。先看 [[01-面向对象#3. 什么是方法重载？什么是方法重写？]] 的定义，再判断发生在编译期还是运行期。

**常见追问**

- `null` 调用多个重载会怎样？（可能选择更具体类型，也可能因候选无唯一最具体方法而编译失败）
- 重写能扩大访问权限吗？（能保持或扩大，不能缩小）

**易错点**

重载不是多态的运行时动态分派；“返回类型不同就是重载”也是错误结论。

## 5. 接口和抽象类有什么区别？

**面试回答**

接口主要定义类型能力和协作契约，一个类可实现多个接口；抽象类用于共享同一类族的状态、构造过程和部分实现，一个类只能直接继承一个类。Java 8 起接口可有 default/static 方法，Java 9 起还可有 private 方法。

**原理与理解**

抽象类可以声明实例字段、构造器、抽象方法和具体实例方法；接口字段隐式为 `public static final`，没有实例构造器。接口方法的能力随 Java 版本演进，不能再简单说“接口只能有抽象方法”。

**成立条件与边界**

抽象类可以完全没有抽象方法，但不能直接实例化。接口 default 方法有冲突规则；接口仍不适合承载每个对象独立的可变实例状态。

**实际场景（通用工程）**

缓存、通知等横向能力通常用接口；若多种订单共享受保护字段、构造校验和模板流程，可考虑抽象基类，但应控制继承层次。

**常见追问**

- 接口能否有方法实现？（能，取决于方法种类和 Java 版本）
- 抽象类能否被 final 修饰？（不能，两者语义冲突）

**易错点**

不要背“接口无实现、无字段，抽象类必须有抽象方法”；这些说法要么过时，要么本来就不成立。

## 6. Java 为什么不支持类的多继承？

**面试回答**

Java 类只能有一个直接父类，主要避免多个父类带来的状态布局、构造顺序和同名实现选择歧义，使类模型更简单。Java 用多接口实现和组合来表达多种能力。

**原理与理解**

若两个父类都提供同签名方法或相同状态，子类需要复杂规则决定继承哪一个。接口可以多继承，但 default 方法冲突必须由更具体接口或实现类显式解决。

**成立条件与边界**

“Java 不支持多继承”只适用于类继承。接口可以 extends 多个接口，类可以 implements 多个接口；这不等于能继承多个类的实例状态和构造器。

**实际场景（通用工程）**

一个服务既可实现 `Retryable` 又实现 `Auditable`，而共享组件通过字段注入或构造器组合，不建立多层业务基类。

**常见追问**

- 多接口 default 方法冲突怎么办？（实现类显式重写并决定调用）
- 为什么接口多继承相对可控？（接口不继承多个父类的实例状态和构造链）

**易错点**

不要回答成“Java 完全没有多继承”；准确说法是“类不支持多父类继承”。

## 7. 一个类可以实现多个接口吗？

**面试回答**

可以，类声明可在 `implements` 后列出多个接口，从而同时承诺多组能力。若接口提供冲突的 default 方法，实现类必须按语言规则消除歧义。

**原理与理解**

类自身或父类中的实例方法优先于接口 default 方法；更具体的子接口默认实现优先。若两个无继承关系的接口提供同签名 default 方法，类需要显式重写。

**成立条件与边界**

泛型接口还有限制：同一泛型接口的不同参数化不能作为同一类的多个超类型，例如不能同时实现 `I<String>` 与 `I<Integer>`。

**实际场景（通用工程）**

领域对象可以同时实现 `Comparable<Order>` 与 `Serializable`；业务服务也可组合多个自定义能力接口。

**常见追问**

- 多个接口声明相同抽象方法怎么办？（签名和返回类型兼容时实现一次即可）
- default 方法如何调用指定父接口版本？（在实现类中使用 `InterfaceName.super.method()`）

**易错点**

“实现多个接口所以 Java 支持类的多继承”不准确；接口不会带来多个父类实例状态和构造链。

## 8. `this` 和 `super` 有什么区别？

**面试回答**

`this` 表示当前对象，可访问当前类成员或委托本类其他构造器；`super` 用于访问直接父类中可见的成员，或调用父类构造器。两者都不能在 static 上下文中作为当前实例使用。

**原理与理解**

字段隐藏时，`this.x` 和 `super.x` 可区分当前类与父类字段；对被重写方法，`super.m()` 明确调用父类实现。构造器链最终必须完成父类构造。

**成立条件与边界**

在 Java 8～21，显式 `this(...)`/`super(...)` 必须是构造器体首条语句。Java 25 的构造器体允许在显式构造器调用前执行受“早期构造上下文”限制的前置语句，因此应给出版本范围；`this(...)` 与 `super(...)` 也不能在同一构造器同时出现。

**实际场景（通用工程）**

构造器用 `this(defaultValue)` 复用校验逻辑；子类覆盖模板步骤后，需要保留父类公共行为时使用 `super.step()`。

**常见追问**

- 构造器能否被继承或重写？（不能）
- 子类构造器不写 `super()` 会怎样？（满足条件时编译器隐式插入无参父构造调用）

**易错点**

“`super(...)` 永远必须是第一条语句”对旧版本成立，但不应写成跨所有 Java 版本的永久结论。

## 9. `static` 修饰变量、方法分别有什么特点？

**面试回答**

static 变量和方法属于类，而不是某个实例。静态变量由该类的运行时表示共享；静态方法按编译期类型选择，不能直接访问实例字段、实例方法或 `this`/`super`。

**原理与理解**

静态成员可通过类名访问。静态方法不参与实例方法的动态分派：子类声明同签名静态方法属于隐藏。静态初始化在类初始化阶段按规范触发和执行。

**成立条件与边界**

“全 JVM 只有一份”过于绝对：同名字节码由不同类加载器定义后是不同的类，各有静态状态。静态共享状态还需要考虑并发可见性和线程安全。

**实际场景（生产能力）**

无状态工具方法适合 static；可变全局计数器若用 static，需要原子性、生命周期、测试隔离和多实例部署方案，不能只加一个字段。

**常见追问**

- static 方法能否被重写？（不能，只能隐藏）
- static 变量一定线程安全吗？（不一定，共享不等于安全）

**易错点**

可通过对象语法访问 static 成员不代表它属于对象；应使用类名，避免误导读者。

## 10. `final` 可以修饰哪些内容？分别有什么作用？

**面试回答**

final 可修饰变量、方法和类。final 变量只能被赋值一次；final 实例方法不能被子类重写；final 类不能被继承。final 引用固定的是引用值，不会自动冻结所指对象。

**原理与理解**

空白 final 字段可在声明处、实例初始化器或每个构造路径中完成赋值。只有满足编译期常量表达式等条件的 `static final` 基本类型或 String 字段才是常量变量，可能被调用方内联。

**成立条件与边界**

final 不等于不可变，也不等于线程安全；`final List` 仍可修改列表内容。final 方法可重载，final 类中的字段也可以是可变对象。

**实际场景（通用工程）**

依赖字段用 `private final` 配合构造器注入，避免对象构造后更换依赖；值对象还需隐藏可变状态和进行防御性复制，不能只加 final。

**常见追问**

- final、finally、finalize 有何区别？（修饰符、异常清理结构、已弃用的对象终结机制）
- final 参数有什么作用？（方法内不能再次赋值该参数变量）

**易错点**

不要把“引用不能改指向”说成“对象内容不能改”；可参考 [[02-Object与String]] 对不可变对象的说明。

## 11. Java 是值传递还是引用传递？

**面试回答**

Java 只有值传递。调用方法时，实参的值被复制给形参：基本类型复制数值，引用类型复制引用值。两个引用值可指向同一对象，因此方法内可修改该对象，但给形参重新赋值不会改变调用方变量。

**原理与理解**

`mutate(list)` 能通过形参调用 `list.add(...)`，是因为形参与实参引用同一对象；`list = new ArrayList<>()` 只改变形参自己的引用值副本。

**成立条件与边界**

语言规范把引用视为一种值，但不承诺它等于可观察的物理内存地址。数组也是对象，传递数组参数同样复制引用值。

**实际场景（通用工程）**

服务方法接收 DTO 后修改字段会被调用方看到；若希望隔离副作用，应复制对象或使用不可变数据，而不是误以为“引用传递”会自动更换外部变量。

**常见追问**

- 能否写方法交换两个 Integer/String 变量？（不能通过重新赋值形参改变调用方变量）
- 为什么能修改 List 内容？（复制的两个引用值指向同一 List）

**易错点**

“基本类型值传递、对象引用传递”是高频错误；引用类型也按值传递，只是被复制的值是引用。

## 12. 成员变量和局部变量有什么区别？

**面试回答**

成员变量声明在类中，分为实例字段和 static 字段，随对象或类的生命周期存在，并有默认值；局部变量声明在方法体、构造器或代码块中，作用域更小，使用前必须明确赋值。

**原理与理解**

字段可使用访问修饰符，并参与对象或类的状态建模；局部变量用于一次执行过程中的临时计算，不能使用 public/private/protected 等成员访问修饰符。

**成立条件与边界**

“成员一定在堆、局部一定在栈”不是 Java 语言规范保证。JIT 可做标量替换、逃逸分析等优化；应从作用域、初始化和生命周期回答，而不是绑定物理存储位置。

**实际场景（通用工程）**

Service 的依赖是成员字段；一次请求的计算结果是局部变量。若把请求数据误放到单例 Bean 的可变成员中，会引入并发串数据风险。

**常见追问**

- 局部变量有默认值吗？（没有，使用前必须明确赋值）
- 实例字段和 static 字段归属有何不同？（对象状态与类状态）

**易错点**

生命周期和存储实现不是同一概念；不要用“都在栈/堆”代替语言层面的准确区别。

## 13. 基本数据类型和引用数据类型有什么区别？

**面试回答**

Java 类型分为基本类型和引用类型。基本类型的值直接属于数值、字符或布尔集合；引用类型的值是对对象或数组的引用，也可能是 `null`。两者在赋值和传参时都复制各自的值。

**原理与理解**

基本类型有固定的语言级取值与运算规则，不能直接调用实例方法；引用类型包括类、接口、数组等，可通过引用访问对象成员。包装类把基本值表示为对象，支持泛型和允许 null 的模型。

**成立条件与边界**

引用值不应简单等同为“对象的物理地址”，其表示由 JVM 实现决定。包装对象也不等同于基本类型，会有 null、身份比较和装箱成本等差异。

**实际场景（通用工程）**

数据库字段可为空时 DTO 常用 `Integer`；确定必有值且参与密集计算时常用 `int`。建模时要明确“缺失”是否是合法状态。

**常见追问**

- String 是基本类型吗？（不是，是类类型）
- 数组是什么类型？（引用类型，数组本身是对象）
- 8 种基本类型有哪些？（见 [[01-面向对象#14. Java 有哪些基本数据类型？]]）

**易错点**

不要说“引用类型按引用传递”；赋值和传参复制的仍是引用值。

## 14. Java 有哪些基本数据类型？

**面试回答**

共 8 种：整数 `byte`、`short`、`int`、`long`；浮点 `float`、`double`；字符 `char`；布尔 `boolean`。

**原理与理解**

整数类型分别是 8、16、32、64 位二进制补码；float/double 分别对应 IEEE 754 单精度/双精度语义；char 是 16 位无符号 UTF-16 代码单元，不一定等于一个完整 Unicode 字符。

**成立条件与边界**

语言规范没有规定 boolean 在对象或数组中的具体存储字节数。金额不应直接依赖二进制浮点精确表示，通常用最小货币单位整数或 `BigDecimal`。

**实际场景（通用工程）**

订单金额用分为单位的 `long` 或规则明确的 `BigDecimal`；遍历 Unicode 文本时，若需要处理补充字符，应按 code point，而不是假定一个 char 就是一个字符。

**常见追问**

- 8 种类型分别是什么？（四整数、两浮点、char、boolean）
- char 能否表示所有 Unicode 字符？（单个 char 不能表示需要代理对的补充字符）

**易错点**

不要背“boolean 占 1 位/1 字节”作为语言保证。包装类型参见 [[01-面向对象#17. Integer 缓存是什么？]]。

## 15. 自动装箱和拆箱是什么？

**面试回答**

装箱是基本类型与对应包装类型之间的转换，例如 `int` 到 `Integer`；拆箱是反向转换。编译器会在允许的上下文中插入相应转换，语义可近似理解为调用 `valueOf` 和 `xxxValue`。

**原理与理解**

`Integer x = 1` 发生装箱，`int y = x` 发生拆箱。装箱结果可能复用已有对象；拆箱需要先取得对象表示的基本值。

**成立条件与边界**

对 null 包装对象拆箱会抛 `NullPointerException`。频繁装箱可能产生分配和间接访问成本；`==` 比较两个包装引用时可能比较对象身份。

**实际场景（生产能力）**

聚合 `List<Integer>` 时先处理 null，再拆箱计算；性能敏感循环优先使用基本类型或专门的基本类型数据结构，并以测量为准。

**常见追问**

- 泛型为什么用 Integer 不能用 int？（泛型类型实参必须是引用类型）
- `Integer a = 1` 是否每次 new？（不一定，装箱允许或要求复用部分值）

**易错点**

“自动”不代表没有异常和成本；null 拆箱与包装类 `==` 是常见线上问题。

## 16. Integer 和 int 有什么区别？

**面试回答**

int 是 32 位基本整数类型，不能为 null；Integer 是不可变包装类，是引用类型，可以为 null，提供解析、比较等方法，并可作为泛型类型实参。

**原理与理解**

字段中的 int 默认值是 0，Integer 默认值是 null；局部变量无论哪种都必须明确赋值后才能读取。二者混合运算通常触发装箱或拆箱。

**成立条件与边界**

Integer 的 `==` 在两边都是引用时比较身份；与 int 混合时通常先拆箱再比较值，但 null 会抛异常。业务字段用哪一种取决于是否需要表达“未提供”。

**实际场景（通用工程）**

分页参数确定必填可用 int；数据库可空列或 PATCH 请求中需要区分“未传”和“传 0”时可用 Integer，并在业务入口校验。

**常见追问**

- Integer 能否为 null？（能）
- Integer 与 int 用 `==` 会怎样？（通常拆箱比较，但 null 会 NPE）

**易错点**

不要把默认值规则套到局部变量，也不要用包装类引用的 `==` 判断数值相等。

## 17. Integer 缓存是什么？

**面试回答**

`Integer.valueOf` 会复用一段小整数对应的 Integer 实例。Java API 至少规定 -128～127 必须缓存；实现可缓存更大范围，所以相同小值装箱后 `==` 常为 true，但业务比较仍应使用 `equals` 或先拆箱。

**原理与理解**

自动装箱的语义会使用装箱转换，`Integer.valueOf` 可从缓存返回对象，`new Integer(...)` 则显式创建新对象且相关构造器已弃用。缓存目的是减少常用小整数对象创建。

**成立条件与边界**

JLS 对某些常量表达式装箱规定了身份相等保证，包含 -128～127 的 int 值；非编译期常量表达式不能照搬同一结论。HotSpot 可通过配置扩大 Integer 缓存上界，这属于实现细节。

**实际场景（通用工程）**

状态码、数量等包装值比较统一使用 `Objects.equals(a, b)` 或明确拆箱后比较，避免测试环境因缓存命中而掩盖生产缺陷。

**常见追问**

- 默认缓存范围是什么？（`Integer.valueOf` 至少 -128～127）
- 为什么 127 的两个 Integer 常 `==`，128 常不等？（前者通常命中缓存，后者是否复用不应作为业务保证）

**易错点**

缓存影响对象身份，不影响数值相等；不要根据 `==` 的偶然结果推断 Integer 的业务值。
