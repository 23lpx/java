# JVM基础

## 472. JVM 是什么？

**面试回答**

JVM（Java Virtual Machine）是 Java 虚拟机，是运行 Java 字节码的抽象计算机，负责加载字节码、分配内存、执行程序、垃圾回收等，让 Java 程序「一次编写，到处运行」。

**理解**

Java 源码编译成 .class 字节码，JVM 解释/执行这些字节码。因为不同平台有各自的 JVM 实现，字节码就能跨平台运行——这就是「跨平台」的由来。JVM 还负责内存管理（GC）、类加载等，是 Java 程序运行的基础环境。

**场景**

项目里打包成 jar 后，部署到不同系统的服务器，只要装了对应 JVM 就能运行，不用改代码。

**常见追问**

- JVM 运行什么？（字节码 .class）
- 跨平台怎么实现？（不同平台有各自 JVM，字节码统一）

**易错点**

JVM 是「运行字节码的虚拟机」，跨平台靠「各平台有对应 JVM」；Java 程序不是直接跑在操作系统上。

## 473. JDK、JRE、JVM 有什么区别？

**面试回答**

JVM 是虚拟机，执行字节码；JRE 是 Java 运行时环境，包含 JVM 和核心类库，用于「运行」Java 程序；JDK 是开发工具包，包含 JRE 和编译器等开发工具，用于「开发」Java 程序。范围 JDK ⊃ JRE ⊃ JVM。

**理解**

三者是「包含关系」：JDK 最大，包含 JRE + 开发工具（javac 编译器、调试工具等）；JRE 包含 JVM + 运行所需类库；JVM 最小，只负责执行字节码。开发要装 JDK，只运行程序装 JRE 即可（现在很多场景 JDK 直接包含 JRE）。

**场景**

项目开发用 JDK（要编译），部署到服务器运行时需要 JRE/JVM 环境。

**常见追问**

- 谁包含谁？（JDK 包含 JRE，JRE 包含 JVM）
- javac 在哪？（JDK 里，是编译工具）

**易错点**

三者是「包含关系」，别并列理解；JDK 开发、JRE 运行、JVM 执行。

## 474. JVM 运行时内存区域有哪些？

**面试回答**

主要分：堆、虚拟机栈、本地方法栈、程序计数器、方法区（JDK 8 后为元空间 Metaspace），另外还有直接内存。

**理解**

按线程是否共享分两类：线程私有的——虚拟机栈、本地方法栈、程序计数器；线程共享的——堆、方法区（元空间）。各区域存不同内容：堆存对象，栈存方法调用和局部变量，方法区存类信息，程序计数器记录执行位置。这是 JVM 内存结构的基础。

**场景**

理解内存区域，才能解释 OOM、栈溢出发生在哪、以及对象分配在堆等实际问题。

**常见追问**

- 哪些线程私有、哪些共享？（见 [[08-JVM/01-JVM基础#475. 哪些区域是线程私有的？]] 和 [[08-JVM/01-JVM基础#476. 哪些区域是线程共享的？]]）
- 方法区在 JDK 8 叫什么？（元空间 Metaspace）

**易错点**

方法区在 JDK 8 后是「元空间」，用本地内存实现；别还停留在「永久代」（那是 JDK 7 及以前）。

## 475. 哪些区域是线程私有的？

**面试回答**

虚拟机栈、本地方法栈、程序计数器，这三块是每个线程独有、线程间隔离的。

**理解**

线程私有意味着每个线程有一份，互不干扰：虚拟机栈存方法调用的栈帧（局部变量等），本地方法栈存本地方法调用，程序计数器记录当前线程执行到哪。因为每个线程执行流程独立，这些区域跟随线程，线程结束就销毁。

**场景**

项目里每个请求线程都有自己独立的虚拟机栈，局部变量互不干扰（这也是局部变量线程安全的原因）。

**常见追问**

- 三个私有区域分别干嘛？（栈存调用、本地栈存 native、计数器记录位置）
- 为什么线程私有？（执行流程各线程独立）

**易错点**

线程私有 = 虚拟机栈、本地方法栈、程序计数器；堆和方法区是共享的，别记混。

## 476. 哪些区域是线程共享的？

**面试回答**

堆和方法区（元空间）是线程共享的，所有线程都能访问。

**理解**

堆存所有线程 new 出来的对象，方法区存类信息、常量等，这些是「全局共享」的数据，所有线程都能访问。正因为堆是共享的，多线程访问堆里的对象才需要并发控制（这也是为什么单例 Bean、共享对象要考虑线程安全）。

**场景**

项目里多个请求线程共享堆里的单例 Bean、共享方法区里的类信息，所以共享可变状态要小心线程安全。

**常见追问**

- 共享区域有哪些？（堆、方法区）
- 共享带来什么问题？（需要并发控制）

**易错点**

线程共享 = 堆 + 方法区；共享区域的并发访问是线程安全问题的根源。

## 477. Java 堆中主要存放什么？

**面试回答**

堆主要存放对象实例和数组，几乎所有 new 出来的对象都在堆里分配，是 GC 主要管理的区域。

**理解**

堆是 JVM 里最大的一块内存，所有 `new` 的对象、数组都放这里。它被所有线程共享，是垃圾回收的主战场（大多数对象在这里分配和回收）。堆还分新生代、老年代（分代收集）。

**场景**

项目里 new 出来的 Dish、Order 等对象都存在堆里，由 GC 管理回收。

**常见追问**

- 堆存什么？（对象实例、数组）
- 谁管理堆？（GC）

**易错点**

堆 = 「对象和数组」，是 GC 重点区域；局部变量在栈里，但对象本身在堆（栈里只存引用）。

## 478. Java 栈中主要存放什么？

**面试回答**

栈（虚拟机栈）主要存放方法调用的栈帧，每个栈帧包含局部变量表、操作数栈、方法返回地址等信息，存的是「基本类型变量」和「对象的引用」，不是对象本身。

**理解**

每调用一个方法就压入一个栈帧，方法结束弹出。栈帧里的局部变量表存方法的局部变量：基本类型直接存值，引用类型存指向堆里对象的引用（对象本体在堆）。栈是线程私有的，方法调用和返回都靠它。

**场景**

项目里方法里的局部变量、基本类型、对象引用都在栈上，方法执行完栈帧弹出、局部变量随之消失。

**常见追问**

- 栈里存对象吗？（不存对象本体，只存引用）
- 栈帧包含什么？（局部变量表、操作数栈、返回地址等）

**易错点**

栈存「局部变量 + 引用」，对象本体在堆；「对象在栈里」是错误说法（除栈上分配优化外）。

## 479. 堆和栈有什么区别？

**面试回答**

堆是线程共享的，存对象实例，由 GC 管理，生命周期长；栈是线程私有的，存方法调用的局部变量和引用，方法结束自动释放，访问快。

**理解**

几个维度：①内容：堆存对象，栈存局部变量/引用；②共享性：堆共享、栈私有；③管理：堆靠 GC 回收，栈自动随方法进出分配释放；④速度：栈快（连续内存、指针移动），堆慢（要分配、GC）；⑤生命周期：堆对象存活到 GC 回收，栈局部变量随方法结束消亡。

**场景**

项目里局部变量在栈（快、自动释放），new 的对象在堆（由 GC 管理）。

**常见追问**

- 谁快？（栈快）
- 谁管对象？（堆，GC 管）

**易错点**

堆和栈的核心区别是「存什么 + 谁管理 + 生命周期」；栈快但存小数据，堆大但靠 GC。

## 480. 程序计数器有什么作用？

**面试回答**

程序计数器记录当前线程正在执行的字节码指令位置（行号），是线程私有的，用于在线程切换后恢复到正确执行位置，保证程序按顺序执行。

**理解**

每个线程都有程序计数器，指向「下一条要执行的指令」。多线程切换时，靠它记住每个线程执行到哪，切回来继续执行。它是 JVM 内存区域里唯一「不会 OOM」的区域（规范里没规定会溢出）。

**场景**

项目里多线程并发执行时，每个线程靠自己的程序计数器记住执行位置，切换后能正确续跑。

**常见追问**

- 它记录什么？（当前执行的指令位置）
- 为什么线程私有？（各线程执行位置独立）

**易错点**

程序计数器是「记录指令位置」的线程私有区域，保证线程切换后能续跑；它是唯一不抛 OOM 的区域。

## 481. 方法区和元空间是什么？

**面试回答**

方法区是 JVM 规范定义的一块内存区域，存类的元信息（类结构、方法、常量、静态变量等）；元空间（Metaspace）是 JDK 8 后对方法区的实现，改用「本地内存」存储，取代了之前的永久代。

**理解**

方法区存「类的元数据」：类名、字段、方法、常量池、静态变量等。JDK 7 及以前用「永久代」实现（在堆里，有固定上限易 OOM）；JDK 8 改用「元空间」，放在本地内存（直接内存），默认只受物理内存限制，可自动扩容，避免了永久代常见的 OOM。

**场景**

项目里加载的类信息、静态变量存元空间；类很多时元空间用本地内存，不易像永久代那样爆。

**常见追问**

- 方法区存什么？（类元信息、常量、静态变量）
- JDK 8 用什么实现方法区？（元空间 Metaspace，本地内存）

**易错点**

JDK 8 后方法区 = 元空间、在「本地内存」；别再说「永久代」（那是 JDK 7 及以前）。

## 482. `new` 一个 Java 对象大致经历什么过程？

**面试回答**

大致：①类加载检查（类是否已加载，没有则先加载）；②在堆中分配内存；③内存初始化（零值）；④设置对象头；⑤执行构造方法 `<init>` 完成初始化，返回引用。

**理解**

new 对象不是简单分配内存：先确保类已加载（类加载器 + 类初始化）；然后在堆上分一块内存（可能触发 GC）；给字段赋默认零值（如 int 默认 0、引用默认 null）；设置对象头（哈希码、GC 分代年龄、类指针等）；最后执行构造器，把字段设成你指定的值。完成后返回对象引用。

**场景**

项目里 `new Dish()` 会经历「类加载检查 → 堆分配 → 零值初始化 → 对象头 → 构造器」这一串过程。

**常见追问**

- 内存分配在哪？（堆）
- 构造方法 `<init>` 做什么？（按代码初始化字段）

**易错点**

new 对象是「类加载 + 堆分配 + 零值 + 对象头 + 构造器」多步过程，别以为只是「执行构造方法」。

## 483. 什么情况下可能发生 StackOverflowError？

**面试回答**

当线程栈深度超限时发生，最常见是「递归调用过深且没有正确终止」导致栈帧不断压栈、栈空间耗尽。

**理解**

每层方法调用都压一个栈帧，栈空间有限。无限递归（或递归太深）会让栈帧越压越多，超出栈容量，抛 StackOverflowError。它是 Error，一般无法恢复，说明代码逻辑有问题（递归没终止条件或终止条件错了）。

**场景**

项目里写递归（如递归遍历树）时，若终止条件有误，就会栈溢出。

**常见追问**

- 典型原因？（递归过深、无终止条件）
- 怎么避免？（正确终止条件、改迭代、控制递归深度）

**易错点**

StackOverflowError 主要在「栈」，典型是「无限/过深递归」；它是 Error，不是 Exception。

## 484. 什么情况下可能发生 OutOfMemoryError？

**面试回答**

当内存不够分配时发生，常见有：堆内存不足（大量对象无法回收）、元空间不足（类太多）、或本地内存不足等，最典型是「堆 OOM」。

**理解**

OOM 表示「没有内存可用了」。堆 OOM 最典型：不断创建对象且都被强引用着（如无限往 List 里 add），GC 也回收不掉，堆满就 OOM。还有元空间 OOM（动态生成太多类）、线程过多导致本地内存耗尽等。OOM 要定位是「哪块内存」爆了。

**场景**

项目里若有内存泄漏（对象一直被引用不释放），长时间运行堆会涨满，最终 OOM。

**常见追问**

- 最常见是哪类？（堆 OOM）
- 和 StackOverflowError 区别？（OOM 是内存不够，栈溢出是栈深度超限）

**易错点**

OOM 是「内存不足」，要区分「堆/元空间/本地内存」哪个爆；典型诱因是内存泄漏或对象无限增长。
