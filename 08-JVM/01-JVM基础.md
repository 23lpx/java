# JVM基础

## 472. JVM 是什么？

**面试回答**

JVM 是执行 Java class 文件格式与字节码指令集的抽象虚拟机规范，也泛指 HotSpot 等具体实现。它负责类加载与链接、字节码执行、运行时内存管理、垃圾回收及与本地环境交互。

**原理与理解**

Java 源码先编译为 class 文件，JVM 可解释执行热点代码，也可由 JIT 编译成本地机器码。统一的 class 文件与 JVM 语义是“一次编译、多平台运行”的基础。

**成立条件与边界**

JVM 不只运行 Java 语言，Kotlin、Scala 等也可生成 JVM 字节码；跨平台依赖目标平台有兼容实现。GC 算法、对象布局和 JIT 都属于实现细节，不由 JVM 规范固定。

**实际场景（通用工程）**

同一 Spring Boot 应用可在不同操作系统的兼容 JDK 上运行，但容器参数、本地库、文件系统和字符集等仍需环境验证。

**常见追问**

- JVM 是规范还是程序？——既可指规范，也常指 HotSpot 等实现，要结合语境。
- 字节码一定逐条解释吗？——不一定，热点路径常经 JIT 编译。

**易错点**

不要把 JVM 等同于 HotSpot，也不要把“跨平台”理解为任何环境都无需适配。

## 473. JDK、JRE、JVM 有什么区别？

**面试回答**

JVM 是执行 class 文件的虚拟机；JRE 是“运行 Java 应用所需环境”的概念，包含 JVM 与标准类库等；JDK 面向开发，除运行能力外还提供 `javac`、`javadoc`、`jlink`、`jcmd` 等工具。

**原理与理解**

开发通常使用 JDK 编译、调试和诊断，部署端需要足够的运行时模块。Java 9 引入模块系统和 `jlink` 后，可以从 JDK 模块生成定制运行时镜像。

**成立条件与边界**

“JDK = JRE + 开发工具”是入门模型，不代表所有厂商和版本都单独发布传统 JRE。现代部署常直接使用 JDK 镜像或 jlink 生成的运行时。

**实际场景（通用工程）**

CI 用 JDK 编译和测试；运行容器可使用兼容 JDK 或定制运行时，同时保留生产诊断所需工具与证书、时区数据。

**常见追问**

- 只运行程序需要 javac 吗？——不需要编译器，但要有应用依赖的运行时模块。
- 为什么生产也可能用 JDK？——便于统一版本并使用 jcmd、jstack 等诊断工具。

**易错点**

不要把已经变化的“独立 JRE 安装包”发行方式当作 Java 平台永恒结构。

## 474. JVM 运行时内存区域有哪些？

**面试回答**

JVM 规范定义 pc 寄存器、JVM 栈、堆、方法区、运行时常量池和可选的本地方法栈。pc、JVM 栈和通常的本地方法栈按线程创建；堆与方法区由线程共享。

**原理与理解**

JVM 栈保存方法调用的帧；堆为类实例和数组分配存储；方法区保存每类结构、运行时常量池、字段/方法数据和代码。运行时常量池是方法区的一部分。

**成立条件与边界**

直接内存、代码缓存、线程本地分配缓冲等是实现或进程层面的重要内存，但不等同于规范列出的运行时数据区。HotSpot 元空间是方法区的一种实现，也不能把两者无条件画等号。

**实际场景（通用工程）**

排查内存问题先按异常、GC 日志和 Native Memory Tracking 区分 Java 堆、元空间、直接内存与线程资源，而不是只调大 `-Xmx`。

**常见追问**

- 哪些区域线程私有？——见 [[08-JVM/01-JVM基础#475. 哪些区域是线程私有的？]]。
- 哪些区域线程共享？——见 [[08-JVM/01-JVM基础#476. 哪些区域是线程共享的？]]。

**易错点**

“运行时区域 = 堆、栈、方法区”过于粗略，也会漏掉 pc、常量池与本地方法栈。

## 475. 哪些区域是线程私有的？

**面试回答**

每个 JVM 线程拥有自己的 pc 寄存器和 JVM 栈；实现若支持本地方法栈，通常也按线程分配。它们在线程创建时建立、线程结束时销毁。

**原理与理解**

每次 Java 方法调用创建栈帧，保存局部变量、操作数栈、动态链接和返回信息。pc 记录当前非 native 方法正在执行的 JVM 指令地址。

**成立条件与边界**

线程私有不等于绝不会出错：栈深度超过限制会抛 StackOverflowError，动态扩展或新建线程栈无法获得内存也可能抛 OOM；执行 native 方法时 pc 值由规范定义为未指定。

**实际场景（通用工程）**

递归调用或创建过多平台线程时，应结合 `-Xss`、线程数、调用深度和本地内存分析，而不是只查看堆占用。

**常见追问**

- 一个方法对应什么？——一次调用对应一个栈帧，同一方法递归会有多个帧。
- 线程结束后这些区域怎样？——随线程生命周期释放。

**易错点**

局部变量的引用值在线程栈帧中，不代表引用指向的对象一定物理存在栈上。

## 476. 哪些区域是线程共享的？

**面试回答**

JVM 规范中的堆和方法区由所有 JVM 线程共享；每类运行时常量池分配自方法区，也随之共享。

**原理与理解**

共享表示线程可通过引用访问同一对象或类元数据，但并不意味着所有共享数据都会发生竞态；不可变对象、线程封闭和同步规则仍决定线程安全。

**成立条件与边界**

JVM 规范没有固定方法区的物理位置。HotSpot 的类元数据主要在本地内存的元空间，而类镜像、静态字段对应值等实现细节不能全部简单归入元空间。

**实际场景（通用工程）**

Spring 单例 Bean 通常位于共享堆中；只有当 Bean 保存可变共享状态且缺少同步时才产生线程安全风险。

**常见追问**

- 共享区域为何需要 GC？——堆对象和可卸载类元数据都可能被回收。
- 共享就一定不安全吗？——不一定，风险来自无序访问可变状态。

**易错点**

“堆共享，所以堆中对象都线程不安全”是错误推导。

## 477. Java 堆中主要存放什么？

**面试回答**

按 JVM 规范，堆是所有线程共享、用于分配类实例和数组的运行时区域，并由自动存储管理系统即 GC 回收不可达对象占用的存储。

**原理与理解**

具体实现可把堆分代、分区或按 Region 管理，堆内存也不要求物理连续。HotSpot 可使用 TLAB 降低多线程对象分配竞争。

**成立条件与边界**

从语言语义看对象分配于堆，但 JIT 经逃逸分析后可能做标量替换、消除分配；因此不能用源码的每个 `new` 推断一定产生可观察的堆对象。

**实际场景（通用工程）**

分析对象增长时结合堆转储、对象直方图和 GC 日志确认哪类对象被保留，不能仅凭代码里 `new` 的数量判断泄漏。

**常见追问**

- 堆必须连续吗？——规范不要求。
- 堆大小固定吗？——可固定，也可在实现允许范围内扩缩。

**易错点**

GC 管理堆不代表所有非 Java 资源都会自动释放，文件、连接仍需显式关闭。

## 478. Java 栈中主要存放什么？

**面试回答**

JVM 栈按线程保存方法调用的栈帧；每帧含局部变量数组、操作数栈、当前类运行时常量池引用，以及完成动态链接、返回和异常派发所需信息。

**原理与理解**

参数和局部值放入局部变量槽，字节码多数运算通过操作数栈完成。方法正常返回或异常退出后，当前帧被丢弃并恢复调用者帧。

**成立条件与边界**

“栈只存基本类型和对象引用”是过度简化，帧还包含执行状态；规范甚至允许帧由实现分配在堆中。JIT 还可能重排或消除物理存储，面试回答应区分逻辑模型与实现。

**实际场景（通用工程）**

线程 dump 展示的是线程调用栈，可用于定位阻塞和递归；它不是堆中对象关系图。

**常见追问**

- 局部变量槽能放什么？——基本值、引用和 returnAddress 等 JVM 类型。
- 方法抛异常后帧怎样？——若本帧无匹配处理器则异常完成并弹帧。

**易错点**

对象引用不是对象本体，也不能把 Java 栈和操作数栈当作同一个概念。

## 479. 堆和栈有什么区别？

**面试回答**

JVM 堆在线程间共享，为对象与数组提供存储并由 GC 管理；JVM 栈按线程保存方法调用帧，随调用进入和退出。两者的作用域、生命周期和失败方式不同。

**原理与理解**

堆不足通常表现为堆 OOM；线程所需栈深超过上限会 StackOverflowError，新建或扩展线程栈缺少本地内存也可能 OOM。

**成立条件与边界**

“栈一定比堆快”不是可靠面试结论：HotSpot 的 TLAB 对象分配也可只是指针碰撞，真实性能由 JIT、缓存和对象生命周期决定。对象是否逃逸还会影响分配优化。

**实际场景（通用工程）**

大量长寿命缓存对象关注堆与 GC；无限递归关注单线程栈；线程数激增则还要关注每线程栈占用和本地内存。

**常见追问**

- `-Xmx` 与 `-Xss` 分别控制什么？——最大堆和每线程栈大小，具体默认值随实现环境变化。
- 调大栈有什么代价？——单线程可递归更深，但同一进程可容纳的线程数可能下降。

**易错点**

不要背“堆大且慢、栈小且快”，应回答用途、共享性、生命周期和异常边界。

## 480. 程序计数器有什么作用？

**面试回答**

每个 JVM 线程都有自己的 pc 寄存器；执行非 native 方法时，它保存当前正在执行的 JVM 指令地址，支持解释、控制流和线程恢复执行。

**原理与理解**

线程切换由操作系统/JVM 保存更完整的线程上下文，pc 是其中与当前 JVM 指令位置相关的抽象部分。分支、跳转和异常处理都会改变后续执行位置。

**成立条件与边界**

执行 native 方法时 pc 值未定义。规范没有为 pc 单独规定 OOM 条件，但“程序计数器永不可能出任何问题”也不是应外推的工程结论。

**实际场景（通用工程）**

理解 pc 有助于阅读字节码控制流；线上线程切换与采样分析还涉及本地指令地址、栈和调度器状态。

**常见追问**

- pc 记录源代码行号吗？——不是，规范层面记录 JVM 指令地址，行号表只是可选调试属性。
- 为什么线程私有？——每个线程有独立执行位置。

**易错点**

不要说 pc “永远指向下一条 Java 源代码”，源码、字节码和机器码是不同层次。

## 481. 方法区和元空间是什么？

**面试回答**

方法区是 JVM 规范定义的共享逻辑区域，保存每类结构、运行时常量池、字段与方法数据以及方法/构造器代码；元空间是 HotSpot 自 Java 8 起存放类元数据的本地内存实现，取代 PermGen。

**原理与理解**

类元数据按 ClassLoader 生命周期管理，类卸载后相关元空间可回收。`MaxMetaspaceSize` 可限制元空间提交量；不设上限也仍受进程和操作系统内存约束。

**成立条件与边界**

不能说“方法区在 JDK 8 后就叫元空间”：前者是规范概念，后者是 HotSpot 实现。字符串池、Class 镜像、静态字段值等位置也不能全部用一句“都在元空间”概括。

**实际场景（通用工程）**

大量动态生成类或 ClassLoader 泄漏可能导致 `OutOfMemoryError: Metaspace`，需要观察类加载/卸载、ClassLoader 统计和本地内存。

**常见追问**

- 元空间一定不会 OOM 吗？——会，受配置和本地内存限制。
- 类何时可卸载？——定义它的 ClassLoader 及其类都满足不可达等条件，并由实现决定回收时机。

**易错点**

PermGen 被移除不等于类元数据不再占内存，也不等于元空间可无限增长。

## 482. `new` 一个 Java 对象大致经历什么过程？

**面试回答**

从典型字节码看，`new` 先解析目标类的符号引用，并在需要时触发类初始化，然后为实例分配存储并把实例字段设为默认值；随后 `dup`、参数压栈和 `invokespecial <init>` 调用构造器完成 Java 级初始化。

**原理与理解**

HotSpot 常从 TLAB 或共享分配区做指针碰撞，并设置对象头和类型信息；构造器先执行父类初始化链，再执行本类实例初始化代码。

**成立条件与边界**

对象头、TLAB、分代位置是 HotSpot 实现细节，不由 JVM 规范固定。JIT 可通过逃逸分析消除分配或做标量替换；`new` 指令和构造器调用是两条不同字节码语义。

**实际场景（通用工程）**

排查对象分配压力时用 JFR、分配采样和 GC 指标确认热点；不能只按源码出现多少个 `new` 估算最终分配量。

**常见追问**

- 字段何时有默认零值？——对象存储分配后、构造器代码赋业务初值前。
- 类初始化和对象初始化一样吗？——不一样，`<clinit>` 面向类，`<init>` 面向实例。

**易错点**

“执行 new 就只是调用构造器”错误；“对象一定进入老年代/新生代某一区”也依收集器和实现而定。

## 483. 什么情况下可能发生 StackOverflowError？

**面试回答**

当某线程计算需要的 JVM 栈或本地方法栈深度超过实现允许的大小时，会抛 StackOverflowError；无终止递归是最常见原因，过深的合法递归或极深调用链也可能触发。

**原理与理解**

每次调用需要新帧，帧大小受局部变量、操作数栈和实现信息影响。`-Xss` 较小时，同样的调用深度更容易达到上限。

**成立条件与边界**

它不同于创建新线程或扩展栈时本地内存不足导致的 OOM。捕获 Error 通常无法解决根因，继续运行是否安全取决于上下文。

**实际场景（通用工程）**

递归遍历用户可控的深层树时，可改为显式栈的迭代算法，并对输入深度设限；先用堆栈跟踪确认重复调用链。

**常见追问**

- 调大 `-Xss` 就解决了吗？——只提高阈值，逻辑错误仍会再次溢出且每线程占用更大。
- 如何区分死循环？——死循环通常不增长调用栈，递归会反复压帧。

**易错点**

StackOverflowError 不只等于“无限递归”，规范条件是线程所需栈超过允许大小。

## 484. 什么情况下可能发生 OutOfMemoryError？

**面试回答**

当 JVM 无法获得完成请求所需的内存且自动内存管理也无法提供时，会抛 OutOfMemoryError。常见来源包括 Java heap、Metaspace、直接/本地内存、GC overhead，以及创建线程失败。

**原理与理解**

原因可能是对象被意外强引用形成泄漏，也可能是正常工作集超过配置。不同错误消息指向不同资源，诊断要结合 GC 日志、堆转储、类加载统计、NMT 和操作系统限制。

**成立条件与边界**

OOM 不等于堆满，也不保证能安全捕获后继续服务；生成 heap dump 本身也需要磁盘和资源。盲目调大 `-Xmx` 可能挤压直接内存、线程栈和系统页缓存。

**实际场景（通用工程）**

`Java heap space` 先分析对象保留链；`Metaspace` 看 ClassLoader；`unable to create native thread` 看线程数、`-Xss` 和系统进程/内存限制。

**常见追问**

- 内存泄漏与内存溢出区别？——泄漏是无用但可达对象持续保留，溢出是最终无法满足分配；需求过大也可溢出而无泄漏。
- 第一现场保留什么？——错误消息、GC 日志、堆转储或类/本地内存数据。

**易错点**

不要把所有 OOM 都归因于“对象太多”或只通过扩大堆处理。
