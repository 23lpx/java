# 线程基础

## 494. 什么是进程？

**面试回答**

进程是操作系统进行资源分配和调度的基本单位，是运行中的程序，拥有独立的内存空间和资源。

**理解**

一个程序跑起来就是一个进程，它拥有独立的内存、文件句柄等资源，进程之间相互隔离。操作系统以进程为单位分配资源。一个进程里可以包含多个线程。进程是「资源分配」的单位。

**场景**

项目里一个 Java 应用启动后就是一个 JVM 进程，拥有独立内存，与其他进程隔离。

**常见追问**

- 进程是哪个单位？（资源分配的基本单位）
- 进程之间共享内存吗？（不共享，相互隔离）

**易错点**

进程是「资源分配单位」，拥有独立内存空间；它是「运行中的程序」，别和线程混淆。

## 495. 什么是线程？

**面试回答**

线程是进程内的执行单元，是 CPU 调度的基本单位；一个进程可以包含多个线程，它们共享进程的资源（内存、文件等）。

**理解**

线程是「实际干活」的：一个进程里可以有多个线程并发执行不同任务。同一进程的线程共享进程的内存等资源，但每个线程有自己的栈和程序计数器。线程是「CPU 调度」的单位，比进程更轻量。

**场景**

项目里一个请求通常由一个线程处理，Tomcat 用线程池里的线程并发处理多个请求。

**常见追问**

- 线程是哪个单位？（CPU 调度的基本单位）
- 同进程线程共享什么？（共享进程资源，但各有自己的栈）

**易错点**

线程是「CPU 调度单位」，共享进程资源；进程是「资源分配单位」，线程是它的执行单元。

## 496. 进程和线程有什么区别？

**面试回答**

进程是资源分配的基本单位，拥有独立内存空间，进程间隔离；线程是 CPU 调度的基本单位，同一进程的线程共享内存资源，创建/切换开销更小。

**理解**

几个维度：①资源：进程独立内存，线程共享进程内存；②调度：线程是 CPU 调度单位，进程是资源单位；③开销：线程创建、切换比进程轻量；④隔离：进程间强隔离，线程间共享内存（需注意线程安全）；⑤关系：一个进程含多个线程。

**场景**

项目里一个 JVM 进程内，Tomcat 用多个线程并发处理请求，线程间共享进程内存（所以共享对象要考虑线程安全）。

**常见追问**

- 谁开销小？（线程）
- 谁共享内存？（线程共享，进程隔离）

**易错点**

核心区别是「资源归属」：进程独立资源、线程共享进程资源；由此引出开销、隔离等差异。

## 497. Java 创建线程有哪些常见方式？

**面试回答**

常见三种：①继承 Thread 类重写 run()；②实现 Runnable 接口；③实现 Callable 接口（有返回值、可抛异常）。实际项目更多用线程池来管理和创建线程。

**理解**

继承 Thread：类继承后 new 出对象直接 start；实现 Runnable：把任务传入 Thread；实现 Callable：配合 FutureTask 获取返回值。三者本质都是「定义任务 + 交给线程执行」。实际开发不直接 new Thread，而是用线程池（Executor）管理线程。

**场景**

项目里一般不手动 new Thread，而是用线程池执行异步任务（如异步记录日志、异步处理），更规范高效。

**常见追问**

- Runnable 和 Callable 区别？（Callable 有返回值、可抛异常）
- 实际开发怎么用？（用线程池，而不是裸 new Thread）

**易错点**

三种方式是「定义任务的方式」，但生产环境推荐用「线程池」而非频繁手动创建线程；Callable 有返回值这点要记住。

## 498. `start()` 和 `run()` 有什么区别？

**面试回答**

start() 会启动一个新线程，由这个新线程去执行 run() 里的逻辑；直接调用 run() 只是普通方法调用，在「当前线程」里顺序执行，不会开新线程。

**理解**

start() 是「真正开启线程」：JVM 创建新线程，新线程进入就绪态等待调度，然后执行 run()。直接调 run() 就把它当普通方法，在当前线程跑，没有并发。所以要用 start() 才能实现多线程。

**场景**

项目里要并发执行任务必须调 start()（或线程池 submit），直接调 run() 等于没开线程、还是单线程执行。

**常见追问**

- 直接调 run() 会怎样？（不开新线程，当前线程顺序执行）
- start() 能调多次吗？（不能，一个线程只能 start 一次）

**易错点**

start() 开新线程、run() 是普通方法；实现多线程必须 start()，这是高频考点。

## 499. Java 线程有哪些状态？

**面试回答**

六种：NEW（新建）、RUNNABLE（就绪/运行）、BLOCKED（阻塞，等锁）、WAITING（无限等待）、TIMED_WAITING（限时等待）、TERMINATED（终止）。

**理解**

NEW：线程对象创建但还没 start；RUNNABLE：可运行（含就绪和运行中）；BLOCKED：等待获取锁被阻塞；WAITING：无限期等待（如 wait()、join() 无参）；TIMED_WAITING：限时等待（如 sleep、wait(timeout)）；TERMINATED：执行完毕。状态之间按条件转换。

**场景**

项目里线程在等锁时是 BLOCKED，调 sleep 是 TIMED_WAITING，调 wait 是 WAITING。

**常见追问**

- 六种状态？（NEW、RUNNABLE、BLOCKED、WAITING、TIMED_WAITING、TERMINATED）
- sleep 让线程进什么状态？（TIMED_WAITING）

**易错点**

Java 线程状态是「六种」，注意 RUNNABLE 合并了「就绪」和「运行」；BLOCKED 和 WAITING 是不同状态。

## 500. `sleep()` 和 `wait()` 有什么区别？

**面试回答**

sleep() 是 Thread 的静态方法，让线程休眠指定时间，不释放锁，醒来继续；wait() 是 Object 的方法，让线程等待，会释放锁，需要被 notify/notifyAll 唤醒。

**理解**

关键区别：①归属：sleep 是 Thread 的，wait 是 Object 的；②锁：sleep 不释放持有的锁，wait 会释放锁；③唤醒：sleep 到点自动醒，wait 要靠 notify/notifyAll 唤醒（或 wait(timeout) 超时）；④使用位置：wait 必须在 synchronized 里调用，sleep 随便。sleep 用于「暂停」，wait 用于「线程间协作等待」。

**场景**

项目里 sleep 用于简单暂停，wait/notify 用于线程间协作（如生产者消费者）。

**常见追问**

- 谁释放锁？（wait 释放，sleep 不释放）
- wait 怎么被唤醒？（notify/notifyAll）

**易错点**

核心区别「sleep 不释放锁、wait 释放锁」，以及 wait 必须配合 synchronized 和 notify 使用，这是高频考点。

## 501. 什么是线程上下文切换？

**面试回答**

线程上下文切换是 CPU 从一个线程切换到另一个线程执行时，保存当前线程的状态（上下文），再加载另一个线程的状态的过程，是有开销的。

**理解**

CPU 核数有限，多线程靠「快速切换」实现并发。切换时要保存当前线程的寄存器、程序计数器、栈信息等（上下文），再恢复另一个线程的上下文。每次切换都有时间和资源开销。所以线程不是越多越好，切换太频繁反而降低性能。

**场景**

项目里线程数过多会导致频繁上下文切换、CPU 被切换开销占满，所以要用线程池合理控制线程数。

**常见追问**

- 切换开销在哪？（保存/恢复线程状态）
- 线程越多越好吗？（不是，切换开销会反噬性能）

**易错点**

上下文切换是「并发的时间代价」；它解释了「为什么线程不是越多越好」，别忽略这个开销。

## 502. 什么叫线程安全？

**面试回答**

线程安全指多个线程并发访问同一个对象/资源时，不需要额外同步也能得到正确的结果，不会出现数据错乱。

**理解**

如果一段代码在多线程下执行，结果始终符合预期（不丢更新、不读脏数据、不越界），就是线程安全的。线程安全的核心是「共享可变状态」的处理：无状态、不可变、或对共享状态正确同步，都能达到线程安全。

**场景**

项目里无状态的 Service（只用局部变量）天然线程安全；共享的计数器等可变状态需要加锁或用原子类才能线程安全。

**常见追问**

- 怎么保证线程安全？（无状态、不可变、加锁、原子类）
- 无状态为什么安全？（没有共享可变状态）

**易错点**

线程安全针对「共享可变状态」；无状态/不可变天然安全，共享可变才需要同步，别把「用了 synchronized 就一定安全」当结论。

## 503. 为什么会出现线程安全问题？

**面试回答**

因为多个线程并发访问「共享的可变数据」，而操作不是原子的（如「读-改-写」被交错执行），导致数据被覆盖、读到中间态，产生错误结果。

**理解**

线程安全问题的三个条件：①多个线程；②共享数据；③数据可变且操作非原子。比如两个线程同时执行 `count++`（读、加、写三步），交错执行导致丢失更新。若没有共享、或数据不可变、或操作原子，就不会有问题。解决思路就是「消除共享/可变，或让操作原子化/加锁」。

**场景**

项目里多个请求线程同时往一个共享 List 里 add，或用非原子方式自增计数，就会出线程安全问题。

**常见追问**

- 三个条件？（多线程、共享、可变且非原子）
- 怎么解决？（加锁、原子类、避免共享）

**易错点**

线程安全问题的根源是「共享可变数据 + 非原子操作」；理解了「读-改-写被交错」就理解了问题本质。
