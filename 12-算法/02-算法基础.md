# 算法基础

## 637. 数组常见题型有哪些？

**面试回答**

数组题常见模式有线性扫描与计数、排序、哈希、双指针、滑动窗口、前缀和/差分、二分、单调栈和动态规划。选择依据是有序性、是否要求连续区间、查询次数、值域与是否允许修改原数组。

**原理与理解**

数组支持 O(1) 下标访问且内存连续，适合用下标维护区间和状态。有序数组可利用单调性二分或对撞；固定区间统计可用前缀和；满足可收缩性质的连续区间可滑窗；最大子数组和含负数时常用 Kadane/DP，而不是盲套滑窗。

**成立条件与边界**

技巧都有前提：二分需要有序或单调谓词，滑动窗口要求移动边界能单调排除状态，前缀和用空间换多次查询。排序会破坏原顺序，并可能丢失原下标关系。

**实际场景（算法题）**

两数之和若数组无序用 HashMap 保留原下标；若已经有序且只求一对，可用左右指针 O(n)；多次区间和查询则预处理 prefix。

**常见追问**

- 连续子数组看到什么技巧？——先考虑前缀和、滑动窗口或 DP，按条件单调性选择。
- 有序数组有哪些优势？——可二分、对撞和去重。
- 原下标不能丢怎么办？——排序对象时携带下标，或使用哈希直接扫描。

**易错点**

不要把“最大子数组和”一律归为滑动窗口；负数会破坏普通窗口的单调收缩逻辑。

## 638. 链表常见题型有哪些？

**面试回答**

高频题型包括反转、合并、删除、找中点/倒数第 K 个、判环与环入口、相交链表、分组处理和链表排序。核心工具是 dummy 节点、快慢指针、前驱/当前/后继以及清晰的指针不变量。

**原理与理解**

链表不能随机访问，定位通常 O(n)，但已知节点附近的插入删除可 O(1)。dummy 统一头节点边界；快慢指针利用速度差找中点或环；反转时必须先保存 next，再改变 current.next，最后推进。

**成立条件与边界**

判环和相交比较的是节点引用身份，不是节点值。单链表删除当前节点通常需要前驱；所谓 O(1) 删除给定节点的技巧不适用于尾节点，且会复制后继值、改变节点语义。

**实际场景（算法题）**

删除倒数第 N 个节点：dummy.next=head，快指针先走 N 步，再与慢指针同步前进，使慢指针停在待删节点前驱，统一处理删除头节点。

**常见追问**

- dummy 的作用？——提供稳定前驱，减少头节点特殊分支。
- Floyd 判环为什么有效？——有环时快慢指针在有限环上最终相遇。
- 反转最易丢什么？——在改 next 前没有保存原后继导致断链。

**易错点**

画清“当前保存了哪些可达节点”再改指针；不要用值相等代替节点相同。

## 639. 栈和队列常见题型有哪些？

**面试回答**

栈适合最近未匹配元素、嵌套结构、表达式、DFS 和单调栈；队列适合 BFS、层序遍历、任务按到达顺序处理；双端队列还能维护滑动窗口候选与 0-1 BFS。

**原理与理解**

栈后进先出，使最近的左括号或待处理操作先匹配；队列先进先出，使 BFS 按距离层扩展。单调栈/队列通过在元素入结构时删除不可能成为答案的候选，保持索引或值的单调不变量。

**成立条件与边界**

单调结构不是保存所有元素，必须说明保存值还是下标以及递增/递减方向。滑动窗口常需保存下标才能判断过期；普通 Queue 也不提供优先级，优先处理应使用 PriorityQueue。

**实际场景（算法题）**

每日温度维护温度单调递减的下标栈；遇到更高温度时不断弹出并计算距离。滑窗最大值则用值递减的 Deque，队首为当前最大候选。

**常见追问**

- 为什么单调栈能线性？——每个元素最多入栈、出栈各一次。
- BFS 为什么用队列？——保证先扩展更少边数的状态。
- 括号匹配栈里存什么？——可存字符或下标，取决于是否需要位置。

**易错点**

不要只背“单调递增/递减”，要从“队首/栈顶需要哪个答案”反推不变量。

## 640. Hash 表常见题型有哪些？

**面试回答**

HashMap/HashSet 常用于存在性、去重、频次、值到下标映射、前缀状态首次位置、分组和记忆化。它以额外空间换取期望 O(1) 的查找与更新。

**原理与理解**

两数之和存已扫描值到下标；前缀和题可存“某前缀值第一次出现位置”；字母异位词可存频次或分组键；滑动窗口可用 Map 维护窗口计数或最后位置。

**成立条件与边界**

O(1) 是期望复杂度，键必须有稳定、正确的 equals/hashCode。值域很小且连续时，数组计数通常更快、更省；需要顺序时应选择 LinkedHashMap/TreeMap 或排序，不要依赖 HashMap 迭代。

**实际场景（算法题）**

最长无重复子串用 Map 保存字符上次位置；发现重复时令 `left = max(left, last+1)`，左边界只向右移动，总复杂度 O(n)。

**常见追问**

- Map 与 Set 怎么选？——只关心存在性用 Set，还需计数/位置等附加值用 Map。
- 为什么保存第一次而非最后一次？——取决于目标，例如最长区间常需最早位置。
- 能否用数组替代 Map？——值域已知且规模可控时可以。

**易错点**

更新前缀状态时“先查还是先写”会影响是否使用当前元素，必须按题意确定。

## 641. 二分查找的基本写法是什么？

**面试回答**

精确查找可维护闭区间 `[left,right]`：循环条件 `left <= right`，比较中点后用 `mid±1` 排除已判断位置。更通用的边界二分是对单调谓词查找第一个 true，关键是先定义区间不变量。

**原理与理解**

```java
int left = 0, right = nums.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) return mid;
    if (nums[mid] < target) left = mid + 1;
    else right = mid - 1;
}
return -1;
```

每轮至少排除 mid，区间严格缩小，因此 O(log n)。

**成立条件与边界**

不仅“数组有序”能二分，答案空间上的真假谓词单调也可以。找左边界、右边界、插入点时循环条件和返回值不同，不能在模板间混用；整数答案二分还要防溢出并验证上下界是否可行。

**实际场景（算法题）**

搜索插入位置本质是找第一个 `nums[i] >= target`；用左闭右开或闭区间模板均可，但先写出“答案始终在哪个区间”的不变量。

**常见追问**

- mid 为什么不写 `(left+right)/2`？——加法可能溢出。
- 重复元素怎样找最左？——相等时继续收缩右侧，并保存候选或使用 lower_bound 模板。
- 旋转数组能二分吗？——可以，每轮至少有一侧有序，据此排除区间。

**易错点**

二分错误多来自区间定义不一致；不要死记一行 while，要逐句验证边界是否会遗漏或死循环。

## 642. 双指针常见场景有哪些？

**面试回答**

双指针包括左右对撞、同向快慢、读写指针和链表速度指针。它适用于存在单调排除规则的两端搜索、原地压缩、区间扫描和链表结构问题。

**原理与理解**

有序两数之和中，和太小只能移动左指针，和太大只能移动右指针；原地去重中 read 扫描输入、write 指向下一个输出位置；链表判环中快慢指针利用速度差。

**成立条件与边界**

双指针不是自动把 O(n²) 变 O(n)，只有每次移动都能证明被跳过状态不可能成为答案时才成立。无序两数之和不能直接对撞，除非先排序且题目允许处理原下标。

**实际场景（算法题）**

有序数组平方：绝对值最大的元素一定在两端，用左右指针比较并从结果数组末尾向前写，O(n) 完成而无需再次排序。

**常见追问**

- 快慢指针有哪些含义？——可能是不同速度，也可能是 read/write 两个同向位置。
- 左右指针为什么不会漏解？——依赖有序性提供的单调排除证明。
- 链表中点偶数长度返回哪个？——由 fast 初值和循环条件决定，要按题意选择。

**易错点**

移动哪个指针必须有证明；“看起来像双指针”不足以保证正确。

## 643. 滑动窗口常见场景有哪些？

**面试回答**

滑动窗口处理连续子数组/子串，分固定长度与可变长度。可变窗口通常右边扩张加入元素，在条件允许单调恢复时左边收缩，并在正确时机更新最长、最短或计数答案。

**原理与理解**

窗口状态常用计数数组、Map、Set、总和或满足条件的种类数维护。最长合法窗口通常先收缩到合法再更新；最短覆盖通常在合法时反复收缩并更新，二者时机不同。

**成立条件与边界**

普通滑窗依赖边界移动的单调性。求正整数数组和至少为 target 的最短子数组可滑窗；允许负数后，右扩不一定让和增大、左缩不一定让和减小，通常要改用前缀和与其他结构。

**实际场景（算法题）**

最长无重复子串维护每个字符计数；右端加入导致重复时移动左端并减计数，直到窗口重新合法，再用 `right-left+1` 更新答案。

**常见追问**

- 固定窗口怎么写？——右端加入，长度超过 k 时移除左端，然后计算窗口答案。
- 最长与最短更新位置为何不同？——最长通常在合法后更新，最短要在合法期间尽量收缩。
- 为什么窗口指针总复杂度 O(n)？——左右指针都只单向移动至多 n 次。

**易错点**

不要写成“满足条件就扩大、不满足就缩小”的万能口诀；不同题目的合法性与目标方向相反。

## 644. BFS 的基本写法是什么？

**面试回答**

BFS 使用队列从起点按层扩展。图搜索在入队时标记 visited，避免同一节点重复入队；无权或每条边权相同的图中，第一次到达节点的层数就是最少边数距离。

**原理与理解**

```java
Deque<Integer> q = new ArrayDeque<>();
boolean[] seen = new boolean[n];
q.offer(start);
seen[start] = true;
int dist = 0;
while (!q.isEmpty()) {
    int size = q.size();
    while (size-- > 0) {
        int u = q.poll();
        if (u == target) return dist;
        for (int v : graph[u]) {
            if (!seen[v]) {
                seen[v] = true;
                q.offer(v);
            }
        }
    }
    dist++;
}
return -1;
```

固定每层 size 可以明确层数，也可直接维护 distance 数组。

**成立条件与边界**

BFS 不直接解决一般带权最短路；非负权通常考虑 Dijkstra，含负权还需其他算法。状态图可能不是原图节点，例如钥匙、方向、剩余步数都可能是 visited 的一部分。

**实际场景（算法题）**

网格最短路把坐标编码为状态，四方向生成邻居，越界、障碍或已访问则跳过；多源问题把所有源点以距离 0 同时入队。

**常见追问**

- 为什么在入队时标记？——防止同一节点被多个前驱重复加入。
- 多源 BFS 怎么初始化？——所有源点先入队并标记为第 0 层。
- 层序遍历为什么记录 size？——固定当前层节点数，新增节点留给下一层。

**易错点**

“第一次到达最短”只对无权/等权边和正确状态建模成立。

## 645. DFS 的基本写法是什么？

**面试回答**

DFS 沿一条分支深入，再返回探索其他分支，可用递归调用栈或显式栈实现。图遍历通常在进入节点时标记 visited；树若结构保证无环，可通过 parent 或天然子节点关系避免回边。

**原理与理解**

```java
void dfs(int u, List<Integer>[] graph, boolean[] seen) {
    seen[u] = true;
    for (int v : graph[u]) {
        if (!seen[v]) {
            dfs(v, graph, seen);
        }
    }
}
```

递归前后还可维护路径状态，用于子树统计、连通分量和路径搜索。

**成立条件与边界**

深图递归可能 StackOverflowError，可改显式栈。visited 是否撤销取决于语义：图遍历的全局访问通常不撤销；枚举不同路径的 path-local 状态通常需要撤销，不能混用。

**实际场景（算法题）**

岛屿数量扫描每个未访问陆地，启动一次 DFS 标记整个连通分量并计数；若网格很大，使用显式栈避免递归深度风险。

**常见追问**

- DFS 与回溯区别？——DFS 是搜索顺序；回溯在 DFS 分支间维护并撤销选择状态。
- 什么时候必须 visited？——一般图存在环时；树遍历也可用父节点避免回边。
- 复杂度？——邻接表遍历通常 O(V+E)，另有递归/栈空间。

**易错点**

不要机械地在所有 DFS 返回时取消 visited，这会让普通图遍历重复访问甚至指数爆炸。

## 646. 回溯的基本模板是什么？

**面试回答**

回溯是对决策树做 DFS：选择一个候选、更新路径与约束、递归探索、再撤销本轮可变状态。它常用于排列、组合、子集、棋盘和约束满足问题，并通过剪枝减少不可能分支。

**原理与理解**

```java
void subsets(int start, int[] nums, List<Integer> path,
             List<List<Integer>> ans) {
    ans.add(new ArrayList<>(path));
    for (int i = start; i < nums.length; i++) {
        path.add(nums[i]);
        subsets(i + 1, nums, path, ans);
        path.remove(path.size() - 1);
    }
}
```

这是子集模板；start 传 i、i+1 或改用 used 数组，分别取决于能否重复选择和是否区分排列顺序，剪枝也应放在能证明分支无解的位置。

**成立条件与边界**

记录结果必须复制 path，否则所有结果可能指向同一可变列表。去重通常先排序，再在同一树层跳过相同候选；“树层去重”和“树枝不可重复使用”不是一回事。若使用不可变新状态，则不一定需要显式撤销。

**实际场景（算法题）**

组合总和先排序，当前值已超过剩余目标时 break 剪枝；允许重复选时递归仍传 i，不允许重复时传 i+1。

**常见追问**

- 排列与组合模板差别？——排列通常从全部候选选并用 used；组合用 start 避免顺序重复。
- 为什么撤销？——恢复父节点状态，让兄弟分支从同一起点探索。
- 回溯复杂度？——通常指数或阶乘级，需结合搜索树与输出规模说明。

**易错点**

忘记复制结果、撤销状态或区分同层去重，是三类最常见错误。

## 647. 二叉树常见遍历方式有哪些？

**面试回答**

深度遍历包括前序根-左-右、中序左-根-右、后序左-右-根；广度遍历是层序。三种 DFS 都可递归或显式栈实现，层序通常用队列。

**原理与理解**

访问根的时机决定前中后序。前序适合自顶向下传状态，后序适合先获得子树结果再合并，中序在满足二叉搜索树不变量时产生非递减键序列；层序天然按深度组织。

**成立条件与边界**

“BST 中序有序”依赖树确实满足 BST 定义及重复键策略。仅凭一种没有空节点标记的遍历通常不能唯一重建任意二叉树；深度很大时递归也可能溢出。

**实际场景（算法题）**

求树高用后序：分别得到左右高度后返回 `max(left,right)+1`；判断路径和可用前序传递剩余值；按层输出使用队列与当前层 size。

**常见追问**

- 迭代中序如何做？——不断压入左链，弹栈访问，再转向右子树。
- 前序和中序能否重建？——键可区分且遍历信息满足条件时可重建。
- Morris 遍历特点？——利用临时线索做到 O(1) 额外空间，但会短暂修改树连接。

**易错点**

前中后序说的是根节点相对左右子树的访问时机，不是节点值大小顺序。

## 648. 堆通常解决什么问题？

**面试回答**

堆用于动态维护当前最小或最大优先级，典型题有 Top K、K 路合并、数据流中位数、任务调度和 Dijkstra 候选。最值查看 O(1)，插入和弹出通常 O(log n)，建堆可 O(n)。

**原理与理解**

求最大 K 个元素维护大小 K 的最小堆，堆顶是候选中最容易淘汰的最小值，复杂度 O(n log k)；求最小 K 个则可用最大堆。双堆可分别维护数据流较小一半和较大一半。

**成立条件与边界**

堆只保证堆顶最优，不保证遍历整体有序。若 K 接近 n，排序或快速选择可能更合适；PriorityQueue 的 decrease-key 支持有限，Dijkstra 常重复入队并在弹出时跳过过期距离。

**实际场景（算法题）**

合并 K 个有序链表时，把每条链表当前头节点放入最小堆；每次弹最小节点写入答案，再把它的 next 入堆，复杂度 O(N log K)。

**常见追问**

- 为什么最大 K 用最小堆？——容量满时能 O(log k) 淘汰 K 个候选中最小者。
- 建堆为什么可 O(n)？——自底向上的 heapify 总下沉成本形成收敛级数。
- 堆排序稳定吗？——通常不稳定。

**易错点**

不要说“堆取出所有元素是 O(n)”；连续 poll n 次通常是 O(n log n)。

## 649. 动态规划的基本思路是什么？

**面试回答**

动态规划适用于具有重叠子问题和可组合最优子结构/计数结构的问题。步骤是定义状态、推导转移、设置 base case、确定无后效依赖的计算顺序、得到答案，并视依赖范围压缩空间。

**原理与理解**

Top-down 记忆化递归按需计算状态，bottom-up tabulation 按依赖顺序填表，本质都是避免重复求同一子问题。状态必须包含决定未来所需的信息，又要尽量精简；转移要覆盖所有合法最后一步且不重复计数。

**成立条件与边界**

DP 不只解决“最优解”，也可求方案数、可达性和概率；并非看到递归就能 DP。若子问题不重叠，分治可能更自然；若局部选择可证明全局最优，贪心可能更简单。原地压缩前必须确认本轮读取的是旧状态还是新状态。

**实际场景（算法题）**

0/1 背包定义 `dp[c]` 为容量 c 的最大价值；一维压缩时容量必须从大到小遍历，防止同一物品在本轮被重复使用。完全背包的遍历方向则不同。

**常见追问**

- 如何设计状态？——从题目答案加上“决定下一步还需要哪些信息”出发。
- 记忆化与递推区别？——计算顺序和实现方式不同，复用子问题结果的思想相同。
- 如何判断遍历方向？——根据转移依赖，确保读取的是期望的上一阶段或当前阶段状态。

**易错点**

不要先套公式再解释 dp 含义；状态定义、转移来源、初始化和遍历顺序必须彼此一致。
