# 反射

## 172. Java 反射是什么？

**面试回答**

反射是 Java 在运行时动态获取类的信息（类名、字段、方法、构造器）并动态操作对象的能力，让程序能「在运行时」检查和调用编译时未知的类。

**理解**

正常写代码是编译期就知道类型；反射则是在运行期通过 Class 对象去「看」一个类的结构，并创建实例、调用方法、读写字段。它是很多框架（Spring、MyBatis、Jackson）的基础，让框架能通用地处理任意类。

**场景**

Spring 用反射创建 Bean、注入依赖，Jackson 用反射序列化对象，项目的 @AutoFill 用反射调用实体类的 setter。

**常见追问**

- 反射的入口是什么？（Class 对象）
- 反射能访问 private 成员吗？（能，但要 setAccessible(true)）

**易错点**

反射是「运行时」动态操作，不是编译期；它强大但有性能和安全（破坏封装）代价。

## 173. 反射可以在运行时做什么？

**面试回答**

可以动态获取类的 Class 对象，拿到字段、方法、构造器信息，并动态创建对象、调用方法、读写字段，甚至访问 private 成员。

**理解**

具体能力：①获取类信息（getName、getFields、getMethods 等）②创建实例（newInstance）③调用方法（Method.invoke）④读写字段（Field.get/set）⑤访问私有成员（setAccessible(true)）。框架就是靠这些能力实现通用逻辑。

**场景**

Spring 用反射实例化 Bean 并注入依赖，MyBatis 用反射把查询结果映射成对象，项目的 @AutoFill 用反射调用 setter 填充字段。

**常见追问**

- 怎么动态创建对象？（Class.newInstance 或 Constructor.newInstance）
- 怎么调用私有方法？（getDeclaredMethod + setAccessible(true)）

**易错点**

反射不仅能「读」还能「写」和「调用」，是运行时动态操作的一整套能力，不只是获取信息。

## 174. 获取 Class 对象有哪些方式？

**面试回答**

三种：①类名.class（如 String.class）②对象.getClass()（如 obj.getClass()）③Class.forName("全限定类名")。

**理解**

第一种编译期就知道类型，最直接；第二种通过已有实例获取；第三种用字符串类名动态加载，最灵活，常用于框架（根据配置的类名加载类）。三种方式拿到的是同一个 Class 对象。

**场景**

Spring 里根据配置的类名字符串用 Class.forName 加载类；日常代码里要拿 Class 用类名.class 即可。

**常见追问**

- Class.forName 和类名.class 区别？（forName 会触发类的静态初始化，且用字符串动态加载）
- 三种方式得到的 Class 是同一个吗？（是）

**易错点**

Class.forName 用「全限定类名」，可能抛 ClassNotFoundException，要处理异常。

## 175. Method 对象是什么？

**面试回答**

Method 是反射 API 中表示「类的一个方法」的对象，通过 Class 对象获取，可以用来查看方法信息并动态调用。

**理解**

通过 `Class.getMethod` 或 `getDeclaredMethod` 拿到 Method 对象，它封装了方法名、参数类型、返回类型等信息，核心方法是 `invoke`——在指定对象上调用这个方法。Method 对象本身不「属于」某个实例，调用时要传目标对象。

**场景**

项目的 @AutoFill 通过反射拿到实体类的 setter 方法（Method 对象），再用 invoke 调用它设置公共字段。

**常见追问**

- 怎么拿到某个方法？（getMethod(name, 参数类型...) 或 getDeclaredMethod）
- invoke 怎么用？（method.invoke(目标对象, 实参...)）

**易错点**

Method 表示「方法」本身，invoke 调用时要传「目标对象 + 参数」；getMethod 只能拿 public 方法，私有方法用 getDeclaredMethod。

## 176. Field 对象是什么？

**面试回答**

Field 是反射 API 中表示「类的一个字段（成员变量）」的对象，通过 Class 获取，可以查看字段信息并动态读写字段值。

**理解**

通过 `Class.getField` 或 `getDeclaredField` 拿到 Field，它能获取字段名、类型，并通过 get/set 在指定对象上读写字段值。访问 private 字段要先 setAccessible(true)。

**场景**

Jackson 序列化/反序列化时用 Field 读写对象字段；项目的 @AutoFill 通过 Field 找到要填充的字段。

**常见追问**

- 怎么读写字段值？（field.get(obj) / field.set(obj, value)）
- 访问私有字段要注意什么？（setAccessible(true)）

**易错点**

Field.get/set 要传「目标对象」；getField 只能拿 public 字段，私有字段用 getDeclaredField。

## 177. `Method.invoke()` 有什么作用？

**面试回答**

Method.invoke 用于在运行时动态调用 Method 对象所表示的方法：传入目标对象和参数，就能执行该方法并返回结果。

**理解**

它是反射「动态调用」的核心。调用格式 `method.invoke(targetObj, args...)`，返回值是方法执行结果。如果方法抛异常，invoke 会包装成 InvocationTargetException。私有方法要先 setAccessible(true) 才能 invoke。

**场景**

项目的 @AutoFill 用反射拿到实体类的 setter 方法，再 `method.invoke(entity, 值)` 动态设置公共字段。

**常见追问**

- invoke 返回什么？（方法执行的返回值）
- 方法抛异常会怎样？（被包装成 InvocationTargetException）

**易错点**

invoke 的两个要素：目标对象 + 参数；目标对象不能是 null（除非是静态方法）。

## 178. 反射有什么优点？

**面试回答**

灵活、通用：能在运行时动态创建对象、调用方法，让框架能处理任意类型，是实现「框架级通用能力」（依赖注入、ORM、序列化、AOP）的基础。

**理解**

反射的最大价值是「解耦到类型未知」：框架写一次，就能处理用户定义的任意类。Spring 的 IoC、MyBatis 的结果映射、Jackson 的序列化、动态代理，都依赖反射。没有反射，框架就得为每个类写死代码，不可能通用。

**场景**

项目里 Spring 用反射创建 Bean、注入依赖，MyBatis 用反射映射查询结果，@AutoFill 用反射填充字段，都受益于反射的通用性。

**常见追问**

- 反射为什么是框架的基础？（让框架能通用处理任意类）
- 反射的核心能力？（运行时获取类信息 + 动态创建/调用）

**易错点**

反射的优点是「灵活通用」，但要同时能说出代价（性能、安全），面试常追问缺点。

## 179. 反射有什么缺点？

**面试回答**

三个主要缺点：①性能较低（运行时动态解析，比直接调用慢）②破坏封装（能访问私有成员）③编译期检查缺失（错误推迟到运行期才暴露）。

**理解**

反射要运行时查找方法、做类型检查、包装参数，比直接调用慢；setAccessible(true) 能绕过 private 限制，破坏封装；用字符串调方法，方法名写错编译期不报错，运行期才抛异常。所以反射适合框架的「通用处」，不适合业务热路径大量使用。

**场景**

项目里业务代码不直接大量用反射；框架（Spring、MyBatis）用反射，但会配合缓存、字节码等手段优化。

**常见追问**

- 反射性能为什么慢？（运行时解析、类型检查、安全检查等开销）
- 怎么缓解性能问题？（缓存 Method/Field、减少重复查找）

**易错点**

反射性能慢是「相对直接调用」而言，现代 JVM 已优化不少，不要夸大成「完全不能用」，关键是用在合适的地方。

## 180. 项目的 AutoFill 为什么需要反射？

**面试回答**

因为 AutoFill 要填充的是「任意实体类」的公共字段（创建时间、创建人、更新时间等），字段名和 setter 因类而异，无法写死，只能用反射在运行时动态找到 setter 并调用。

**理解**

公共字段填充是切面，切面不知道当前处理的是 Dish 还是 Setmeal 还是 Category，字段可能都叫 createTime、updateUser，但类不同。反射让切面能：根据实体类的 Class 拿到对应字段的 setter 方法，再统一调用填充。这样一套逻辑适配所有实体类，不用每个类写一遍。

**场景**

项目里 @AutoFill 切面通过反射获取实体类（如 Dish）的 setCreateTime、setUpdateUser 等方法，动态填入当前时间和操作人。

**常见追问**

- 不用反射行不行？（那就得为每个实体类各写一段填充代码，无法通用）
- 反射在这里具体怎么做？（拿到 Class → 找 setter 的 Method → invoke 填值）

**易错点**

AutoFill 用反射的动机是「通用处理不同实体类」，核心是消除重复、适配任意类。

## 181. 为什么不直接调用实体类 setter？

**面试回答**

因为切面处理的是「通用逻辑」，它在编译期不知道具体是哪个实体类，没法写死 `dish.setCreateTime(...)` 这种调用，只能用反射在运行时根据实际类型动态调用对应的 setter。

**理解**

如果直接调用 setter，就得针对每个实体类写一段代码（if 是 Dish 调 Dish 的 setter，if 是 Setmeal 调 Setmeal 的 setter），又臭又长，而且每加一个新实体类都要改切面。用反射，拿到实体类的 Class，按字段名动态找到 setter 调用，一套代码通用，新增实体类也无需改切面。

**场景**

项目里新增一个实体类（如 Category），只要它字段符合约定，@AutoFill 反射逻辑自动生效，不需要为它单独写填充代码。

**常见追问**

- 直接调用 setter 的缺点？（每个类都要写、不通用、难扩展）
- 反射怎么避免写死类？（运行时根据对象的实际 Class 找方法）

**易错点**

核心是「编译期类型未知 vs 运行时动态」：切面要通用，就必须靠反射消除对具体类的硬编码依赖。
